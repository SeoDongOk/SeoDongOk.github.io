FreeCodeCamp의 _Algorithmic Trading: Machine Learning & Quant Strategies_ 강의를 따라
S&P 500 종목에 기술적 지표 6종을 붙였다. Garman-Klass Volatility, RSI, 볼린저밴드,
ATR, MACD, Dollar Volume.

코드는 **에러 없이 잘 돌아갔다.** 지표 컬럼도 예쁘게 붙었다. 여기서 그냥 다음 단계
(K-Means 클러스터링)로 넘어갈 뻔했는데, 그 전에 "이 숫자들이 정말 내가 생각한 그 숫자인가"를
한 번 확인해보기로 했다.

결과적으로 **4가지 문제**를 찾았다. 전부 에러를 내지 않고 조용히 지나가는 종류였다.

## 검증 환경

```
Python 3.11 / pandas 2.2.1 / numpy 1.26.4 / pandas_ta 0.3.14b0 / yfinance 1.7.0

단일 종목 검증: AAPL 일봉 2,012개 (2015-09-29 ~ 2023-09-26)
종목풀 검증  : 30종목 일봉 60,360행 -> 월말 집계 2,850행
```

## 발견 1 — MACD의 `length` 파라미터는 무시되고 있었다

강의 코드는 이렇게 생겼다.

```python
def compute_macd(close):
    macd = pandas_ta.macd(close=close, length=20).iloc[:, 0]
    return macd.sub(macd.mean()).div(macd.std())
```

`length=20`. 20일 기준 MACD를 쓰겠다는 의도로 읽힌다. 그런데 `pandas_ta.macd()`의 시그니처는
`macd(close, fast, slow, signal, ...)`다. **`length`라는 파라미터가 없다.**
없는 인자는 `**kwargs`로 흘러들어가 조용히 버려진다.

세 가지 값을 넣고 기본값과 비교해봤다.

```
length=10 vs (12,26,9) 완전동일: True   최대절대차: 0.0000000000
length=20 vs (12,26,9) 완전동일: True   최대절대차: 0.0000000000
length=50 vs (12,26,9) 완전동일: True   최대절대차: 0.0000000000

실제로 fast=10, slow=20 을 주면?      최대절대차: 1.9321  (완전동일: False)
```

`length`에 뭘 넣든 결과가 **비트 단위로 동일**하다. 반면 진짜 파라미터를 바꾸면 값이 확 달라진다.

결정적 증거는 반환 컬럼명이었다.

```python
>>> pandas_ta.macd(close=d['adj close'], length=20).columns
['MACD_12_26_9', 'MACDh_12_26_9', 'MACDs_12_26_9']
```

`length=20`을 넣었는데 컬럼명이 `MACD_12_26_9`. 라이브러리가 자기 입으로 "나 기본값 썼다"고
말하고 있었던 셈이다. 6개월 뒤에 "MACD 기간을 20으로 튜닝했는데 성과가 그대로네"라고
헤맬 뻔했다.

```python
# 수정
macd = pandas_ta.macd(close=close, fast=12, slow=26, signal=9).iloc[:, 0]
```

**교훈**: 파라미터를 넣었으면 그게 반영됐는지 반환값에서 확인하자. `**kwargs`를 받는
라이브러리는 오타를 잡아주지 않는다.

## 발견 2 — Garman-Klass에 수정주가를 섞으면 변동성이 4.6배 부풀려진다

Garman-Klass 변동성 추정치의 원식은 이렇다.

```
GK = 0.5 * ln(H/L)^2 - (2*ln2 - 1) * ln(C/O)^2
```

강의 코드는 `C` 자리에 `adj close`(수정주가)를 넣는다.

```python
df['garman_klass_vol'] = (
    ((np.log(df['high']) - np.log(df['low']))**2) / 2
    - (2*np.log(2) - 1) * ((np.log(df['adj close']) - np.log(df['open']))**2)
)
```

문제는 `high`, `low`, `open`은 **비수정주가**라는 것이다. 배당·액면분할 조정이 들어간
`adj close`와 조정이 안 된 `open`을 나누면, 그 비율에는 주가 움직임이 아니라
**조정계수**가 섞여 들어간다.

AAPL 4:1 액면분할(2020-08-31) 전후를 찍어봤다.

```
날짜         close   adjclose   GK(adj close)      GK(close)
2020-08-27   125.01   121.15        -0.00048       0.000312
2020-08-28   124.81   120.96        -0.00054       0.000075
2020-08-31   129.04   125.06         0.00060       0.000707
2020-09-01   134.18   130.04         0.00035       0.000474
2020-09-02   131.40   127.34         0.00112       0.002619
```

`adj close` 버전은 **음수**가 나온다. 변동성 추정치가 음수인 건 그 자체로 신호다.
전체 기간 통계를 보면 왜곡의 크기가 드러난다.

```
GK(adj close) 표준편차 0.00144
GK(close)     표준편차 0.00031   ->  4.6배 팽창
```

핵심은 조정계수가 **시간에 따라 변한다**는 점이다. 배당이 쌓일수록
`adj close / close` 비율이 달라지므로, `ln(adj close) - ln(open)`에는 날짜에 따라
크기가 변하는 체계적 오프셋이 얹힌다. 이걸 제곱하니 노이즈가 증폭된다.

```python
# 수정 — high/low/open 과 동일한 비수정주가로 통일
- (2*np.log(2) - 1) * ((np.log(df['close']) - np.log(df['open']))**2)
```

**교훈**: 한 수식 안에서 수정주가와 비수정주가를 섞지 말 것. OHLC는 한 세트로 움직인다.

## 발견 3 — 볼린저 3개 밴드는 "가격" 3벌이었다 (가장 심각)

이게 제일 뼈아팠다. 강의 코드는 볼린저밴드의 하단·중단·상단을 각각 피처로 만든다.

```python
df['bb_low']  = ... bbands(close=np.log1p(x), length=20).iloc[:, 0]
df['bb_mid']  = ... bbands(close=np.log1p(x), length=20).iloc[:, 1]
df['bb_high'] = ... bbands(close=np.log1p(x), length=20).iloc[:, 2]
```

피처 3개가 늘었다고 생각했다. 30종목 월말 데이터로 상관을 재봤다.

```
                  gk_vol   rsi  bb_low  bb_mid  bb_high   atr  macd
garman_klass_vol    1.00 -0.17   -0.10   -0.09    -0.07  0.35 -0.15
rsi                -0.17  1.00    0.02    0.01     0.01 -0.17  0.79
bb_low             -0.10  0.02    1.00    1.00     1.00  0.20  0.04
bb_mid             -0.09  0.01    1.00    1.00     1.00  0.22  0.03
bb_high            -0.07  0.01    1.00    1.00     1.00  0.24  0.03
atr                 0.35 -0.17    0.20    0.22     0.24  1.00 -0.17
macd               -0.15  0.79    0.04    0.03     0.03 -0.17  1.00
```

`bb_low`, `bb_mid`, `bb_high`가 서로 **1.00**. 소수점을 더 보면 0.9993, 0.9993, 0.9971이다.
그리고 결정타.

```
bb_mid ~ log1p(adj close) : 0.9991
```

당연한 얘기다. 볼린저 중단선은 정의상 **20일 이동평균**이고, 상·하단은 거기에
표준편차를 더하고 뺀 값이다. 세 밴드의 절대 레벨은 전부 "지금 주가가 얼마인가"를
되풀이한다. 20일 평균은 원계열을 거의 그대로 따라간다.

즉 피처를 3개 추가한 게 아니라 **가격을 3번 넣은 것**이다.

상관행렬의 고유값을 뽑아보면 확실해진다.

```
7개 피처의 주성분 설명비율:
[0.439  0.282  0.166  0.084  0.029  0.000  -0.000]
                                    ^^^^^  ^^^^^^
                            고유값 0 = 완전 선형종속
```

마지막 두 고유값이 **정확히 0**이다. 상관행렬의 rank가 7이 아니라 5라는 뜻이고,
"세 밴드 중 두 개는 나머지로 완벽하게 표현된다"는 수학적 확인이다.
누적 분산 95%에 필요한 주성분은 **4개**뿐이었다.

K-Means는 유클리드 거리로 군집을 나눈다. 여기에 사실상 같은 축을 3번 넣으면
그 축에 3배 가중치가 걸린다. **가격 수준으로 종목을 나누는 클러스터링**이 되어버린다.
비싼 주식 군집, 싼 주식 군집. 전략적으로 아무 의미가 없다.

### 고치는 법 — 밴드의 "레벨"이 아니라 "위치"와 "폭"을 쓴다

볼린저밴드에서 정보를 갖는 건 밴드의 절대 위치가 아니라, **가격이 밴드 안에서
어디쯤 있는가**(%B)와 **밴드가 얼마나 벌어져 있는가**(bandwidth)다.

```python
lp       = np.log1p(data['adj close'])
pct_b    = (lp - data['bb_low']) / (data['bb_high'] - data['bb_low'])
bb_width = (data['bb_high'] - data['bb_low']) / data['bb_mid']
```

바꾸고 나니 가격 의존성이 사라졌다.

```
pct_b    ~ log1p(가격) :  0.0194     (기존 bb_mid 는 0.9991)
bb_width ~ log1p(가격) : -0.4370

밴드폭 ~ garman_klass_vol : 0.4747
밴드폭 ~ atr              : 0.5065
```

`pct_b`는 가격 수준과 거의 무관해졌고(0.0194), `bb_width`는 다른 변동성 지표들과
0.47~0.51로 **적당히** 상관된다. 같은 현상을 다른 각도에서 보는 지표라면 이 정도가 건강하다.

주성분 구조도 달라졌다.

```
기존 7개 : [0.439 0.282 0.166 0.084 0.029 0.000 -0.000]  -> 실질 rank 5
개선 6개 : [0.435 0.262 0.121 0.097 0.069 0.017]          -> 실질 rank 6, 0 없음
```

**교훈**: 피처를 추가했으면 상관행렬을 찍어보자. 고유값에 0이 있으면 그건 피처가 아니라 중복이다.

## 발견 4 — z-score 정규화가 미래를 보고 있었다

ATR과 MACD는 이렇게 정규화된다.

```python
return atr.sub(atr.mean()).div(atr.std())
```

깔끔해 보이지만 `atr.mean()`과 `atr.std()`는 **전체 기간**의 통계다.
2016년 6월의 피처를 계산하는 데 2023년 데이터가 쓰인다. 실전에서는 존재할 수 없는 정보다.

전체기간 z-score와, 그 시점까지만 쓰는 expanding z-score를 비교했다.

```
상관계수      : 0.5679
평균절대차    : 1.322
최대절대차    : 6.439
부호 뒤집힘   : 38.9%
```

**38.9%.** 열흘 중 나흘은 "이 종목이 지금 고변동인가 저변동인가"라는 판정 자체가 뒤집힌다.
상관도 0.57로, 같은 지표라고 부르기 민망한 수준이다.

시점별로 보면 왜곡의 방향이 보인다.

```
날짜          ATR    전체기간 z    expanding z
2016-06-30   0.43      -1.05         -1.47
2018-06-29   0.73      -0.86         +0.80    <- 부호 반전
2020-03-20   4.37      +1.49         +7.14    <- 코로나 폭락
2022-06-30   4.73      +1.72         +2.04
```

2020년 3월 코로나 폭락장을 보자. 그 시점까지의 정보만 쓰면 z = **+7.14**, 역사상 유례없는
변동성이다. 반면 전체기간 통계를 쓰면 **+1.49**로 쪼그라든다. 2020~2022년의 높은 변동성을
"이미 알고" 평균과 표준편차에 반영해버렸기 때문이다.

백테스트에서 이런 피처를 쓰면, 모델은 폭락을 폭락으로 인식하지 못한다. 그리고
성과는 실제보다 좋게 나온다.

```python
# 수정
atr.sub(atr.expanding().mean()).div(atr.expanding().std())
```

같은 문제가 수익률 아웃라이어 클리핑에도 있다. `x.quantile(0.005)` 역시 전체 기간 분위수다.

## 발견 5 — RSI와 MACD는 0.79로 겹친다

상관행렬로 돌아가보면 `rsi ~ macd = 0.79`다. 둘 다 가격 모멘텀을 보는 오실레이터니
당연하지만, 0.79면 독립적인 피처 2개라기보다 **하나의 모멘텀 축**에 가깝다.

개선안에서도 `pct_b ~ rsi = 0.82`로 여전히 높다. 정직하게 말하면 이건 완전히
해결하지 못했다. 모멘텀 계열에서 하나만 남기거나, 셋을 묶어 하나의 합성 팩터로
만드는 편이 나을 것 같다. 다음 과제로 남긴다.

## 워밍업 구간 정리

지표마다 초기 NaN 길이가 다르다. `dropna()` 한 방에 날아가는 양이 여기서 결정된다.

```
garman_klass_vol   NaN   0개   첫 유효값 2015-09-29
atr(14)            NaN  14개   첫 유효값 2015-10-19
bb_low(20)         NaN  19개   첫 유효값 2015-10-26
rsi(20)            NaN  20개   첫 유효값 2015-10-27
macd(12,26,9)      NaN  25개   첫 유효값 2015-11-03
```

가장 긴 MACD(25일)가 전체 시작점을 결정한다. 여기에 월말 집계 → 5년 롤링 유동성 필터
→ 12개월 수익률 계산이 겹치면서, 8년치 데이터가 최종적으로 **72개월(2017-10 ~ 2023-09)** 로 줄었다.
96개월 중 24개월, 그러니까 **약 25%가 워밍업과 필터로 증발**했다. 12개월 수익률 하나 때문에
1년이 통째로 날아가는 게 가장 크다.

## 정리

| #   | 문제               | 실측 근거                                            | 조치                    |
| --- | ------------------ | ---------------------------------------------------- | ----------------------- |
| 1   | MACD `length` 무시 | length=10/20/50 결과 완전동일, 컬럼명 `MACD_12_26_9` | `fast/slow/signal` 명시 |
| 2   | GK에 수정주가 혼용 | 표준편차 4.6배 팽창, 분할일 음수 발생                | `close`로 통일          |
| 3   | 볼린저 3밴드 중복  | 상호상관 1.00, `bb_mid~가격` 0.9991, 고유값 0        | %B + 밴드폭으로 교체    |
| 4   | z-score look-ahead | 상관 0.57, 부호 뒤집힘 38.9%                         | `expanding()` 기준      |
| 5   | RSI~MACD 중복      | 상관 0.79                                            | 미해결, 과제로 남김     |

7개 피처를 만들었다고 생각했지만, 분산의 95%를 설명하는 데 필요한 축은 **4개**였고
행렬의 실질 rank는 **5**였다. 성격별로 묶으면 **모멘텀**(RSI·MACD, 상관 0.79),
**변동성**(GK·ATR, 상관 0.35), **가격 레벨**(볼린저 3밴드) 세 덩어리다.
다만 GK와 ATR의 0.35는 "완전히 같은 축"이라기엔 약한 값이라, 실제 독립 차원은
세 개와 다섯 개 사이 어딘가로 보는 게 정직하다.

## 배운 점

**에러가 안 나는 것과 맞는 것은 다르다.** 이번에 찾은 4가지는 전부 예외를 던지지 않았다.
`length=20`은 조용히 버려졌고, 수정주가 혼용은 그럴듯한 숫자를 뱉었고, 볼린저 3밴드는
정상적으로 컬럼이 생겼고, z-score는 평균 0 표준편차 1로 예쁘게 정규화됐다.
전부 "돌아가는" 코드였다.

**피처를 만들었으면 상관행렬부터 찍자.** 30종목 월말 데이터로 상관 한 번 재는 데
1분 걸렸다. 그 1분으로 "가격을 3번 넣고 있었다"는 사실을 알았다. 클러스터링을
먼저 돌렸다면 결과가 이상해도 원인을 못 찾고 하이퍼파라미터만 만졌을 것이다.

**강의 코드는 동작하는 예제지, 검증된 코드가 아니다.** 강의의 목적은 파이프라인 전체
흐름을 보여주는 것이고 그 목적은 충분히 달성한다. 다만 그대로 실전에 옮기면
look-ahead bias가 그대로 따라온다. 따라 친 다음에 한 줄씩 되묻는 과정이 결국 본론이었다.

expanding z-score부터 반영하고 갈 생각이다.
