## 시험 직전 빈출도

> **우선순위 S · ★★★★★**
>
> ACID는 2020·2021년 실기 이력이 있고 로킹·회복 기법까지 묶여 반복 대비 가치가 높다.

- **최소 암기:** ACID, 갱신 분실·비완료 의존·모순성·연쇄 복귀, 2단계 로킹, 즉시/지연 갱신
- **5점 후보:** 원자성=전부 또는 전무 / 일관성=제약 유지 / 격리성=중간 결과 차단 / 지속성=완료 결과 영구
- **판정 기준:** 별점은 Q-Net의 공식 출제 확률이 아니다. 2020년 1회~2026년 1회 복원 목록과 2026 시나공 핵심요약의 실기 출제 이력 표기를 개념군 단위로 교차해 정한 **시험 전날 상대 우선순위**다.

트랜잭션 문제는 ACID 네 가지 특성과 병행 처리 중 발생하는 문제를 구분하는 것이 핵심이다. 특히 **행의 값 변화**와 **행 집합 변화**를 나눠야 한다.

## 1. 트랜잭션

데이터베이스에서 하나의 논리적 기능을 수행하는 작업 단위다.

```text
BEGIN → 여러 연산 → COMMIT 또는 ROLLBACK
```

## 2. ACID

| 특성   | 의미                               | 식별어         |
| ------ | ---------------------------------- | -------------- |
| 원자성 | 전부 수행하거나 전부 취소          | All or Nothing |
| 일관성 | 전후에 무결성 규칙 유지            | 유효한 상태    |
| 격리성 | 동시 트랜잭션이 서로 간섭하지 않음 | 독립 실행      |
| 영속성 | 커밋 결과를 영구 보존              | 장애 후 유지   |

암기:

```text
원일격영
원자성-일관성-격리성-영속성
```

## 3. 트랜잭션 상태

| 상태      | 의미                               |
| --------- | ---------------------------------- |
| 활동      | 트랜잭션 연산 수행 중              |
| 부분 완료 | 마지막 연산까지 수행했지만 커밋 전 |
| 완료      | 커밋되어 정상 종료                 |
| 실패      | 오류로 더 진행할 수 없음           |
| 철회      | 롤백되어 이전 상태로 복구          |

## 4. TCL

| 명령      | 의미                                |
| --------- | ----------------------------------- |
| COMMIT    | 변경사항을 영구 반영                |
| ROLLBACK  | 변경사항을 취소                     |
| SAVEPOINT | 트랜잭션 내부의 중간 복구 지점 설정 |

## 5. 병행 처리 문제

| 현상                | 의미                                           |
| ------------------- | ---------------------------------------------- |
| 갱신 분실           | 한 트랜잭션의 갱신이 다른 갱신에 덮임          |
| Dirty Read          | 커밋되지 않은 데이터를 읽음                    |
| Non-repeatable Read | 같은 행을 다시 읽었는데 값이 달라짐            |
| Phantom Read        | 같은 조건으로 다시 조회했는데 행 집합이 달라짐 |

```text
값이 바뀜 = Non-repeatable Read
행이 생기거나 사라짐 = Phantom Read
미커밋 값 읽음 = Dirty Read
수정 결과가 덮임 = Lost Update
```

## 6. 로킹

트랜잭션이 데이터에 접근하기 전에 잠금을 설정하여 다른 트랜잭션의 접근을 제어한다.

| 잠금      | 의미                             |
| --------- | -------------------------------- |
| 공유 잠금 | 읽기용, 다른 공유 잠금 허용      |
| 배타 잠금 | 쓰기용, 다른 공유·배타 잠금 제한 |

### 로킹 단위

```text
단위가 큼 → 잠금 수 감소, 관리 비용 감소, 병행성 감소
단위가 작음 → 잠금 수 증가, 관리 비용 증가, 병행성 증가
```

## 7. 2단계 로킹

| 단계      | 동작                              |
| --------- | --------------------------------- |
| 확장 단계 | 잠금 획득 가능, 해제 불가         |
| 축소 단계 | 잠금 해제 가능, 새 잠금 획득 불가 |

직렬 가능성을 보장하지만 교착상태가 발생할 수 있다.

## 8. 타임스탬프 순서 기법

트랜잭션에 고유한 시간값을 부여하고 시간 순서에 따라 실행 순서를 결정한다.

- 잠금을 사용하지 않으므로 교착상태가 발생하지 않는다.
- 순서 위반 트랜잭션은 취소 후 재시작할 수 있다.

## 9. 격리 수준

| 수준             | 방지 범위                             |
| ---------------- | ------------------------------------- |
| Read Uncommitted | 가장 낮음, Dirty Read 가능            |
| Read Committed   | Dirty Read 방지                       |
| Repeatable Read  | Dirty Read와 Non-repeatable Read 방지 |
| Serializable     | 세 현상을 모두 방지, 가장 강함        |

격리 수준이 높아질수록 일관성은 증가하지만 일반적으로 동시성은 감소한다.

## 10. 회복

장애 발생 전의 일관된 상태로 데이터베이스를 복원하는 작업이다.

| 연산 | 의미                                 |
| ---- | ------------------------------------ |
| REDO | 커밋된 트랜잭션의 변경을 다시 적용   |
| UNDO | 커밋되지 않은 트랜잭션의 변경을 취소 |

## 11. 로그 기반 회복

### 지연 갱신

- 트랜잭션 완료 전에는 DB에 실제 변경을 반영하지 않는다.
- 커밋 후 로그를 이용해 REDO한다.
- 미완료 변경이 DB에 없으므로 일반적으로 UNDO가 불필요하다.

### 즉시 갱신

- 트랜잭션 완료 전에도 DB에 변경을 반영할 수 있다.
- 장애 시 미완료 트랜잭션은 UNDO한다.
- 완료 트랜잭션은 필요하면 REDO한다.

## 12. 체크포인트와 그림자 페이징

| 기법          | 의미                                                  |
| ------------- | ----------------------------------------------------- |
| 체크포인트    | 일정 시점의 DB와 로그 상태를 기록해 회복 범위 축소    |
| 그림자 페이징 | 현재 페이지 테이블과 그림자 페이지 테이블을 별도 유지 |

## 13. 시험 직전 암기

```text
전부 또는 전무 = 원자성
전후 무결성 = 일관성
서로 간섭하지 않음 = 격리성
커밋 결과 영구 보존 = 영속성
미커밋 데이터 읽기 = Dirty Read
같은 행 값 변화 = Non-repeatable Read
행 집합 변화 = Phantom Read
확장 후 축소 = 2단계 로킹
완료 변경 재적용 = REDO
미완료 변경 취소 = UNDO
회복 범위 축소 = 체크포인트
```
