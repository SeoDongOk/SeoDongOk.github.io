[Echo 인프라 시리즈 전체 목차](/blog/2026-11-05-echo-infra-series)

> 2026년 11월 4일 기준 해커톤 구현 회고입니다. 당시 코드와 작업 기록을 기준으로 정리했으며, 현재 서비스 상태나 모든 환경에 적용되는 설정을 보장하지 않습니다.

## 기술 명칭과 설명

OIDC는 작업 주체가 누구인지 서명된 토큰으로 증명하는 규약입니다. AWS STS는 신뢰 조건을 통과한 주체에게 짧은 수명의 자격 증명을 줍니다. GCP WIF는 외부 신원을 Google 신원과 연결합니다. 인증은 누구인지 확인하는 것이고 권한은 무엇을 할 수 있는지 정하는 것입니다.

## 내가 무엇을 했는가

Terraform plan 역할과 빌드 역할을 구분하고, AWS ci-build·Google 연합 executor 역할, GCP ci-build 서비스 계정과 관제탑 신원을 준비했습니다. 저장소 목록을 공통 모듈로 정리하고 실행기 자격 증명 계약을 작성했습니다.

## 트러블슈팅: 문제 → 원인/판단 → 조치

echo-was 빌드 신원에 PR ref까지 허용되는 과도한 신뢰 범위가 있었습니다. 8a2fc71에서 echo-was는 main만, echo-infra는 plan에 필요한 main·PR을 허용하도록 분리했습니다. Google ID 토큰 azp 관련 후속 수정 6f14084는 API 담당 작성이므로 본인 구현으로 포함하지 않습니다.

## 해결 결과와 아직 남은 한계

당시 적용 기록에서 main 전용 WIF 적용을 확인했습니다. 같은 기록에는 ci-build의 프로젝트 범위 container.developer 축소가 잔여 과제로 있습니다. 장기 키를 없앤 것과 최소 권한을 완성한 것은 다릅니다.

## 기여 범위와 검증 기준

본인 작성의 비병합 커밋과 변경 내용을 대조했습니다. 코드 구현, 적용 기록, 실측 결과는 구분합니다. 팀원이 만든 기반을 확장한 작업은 그 경계를 본문에 명시했고, 목표 수치는 완료 성과로 표현하지 않았습니다. 운영 경로와 식별자는 공개본에서 생략했습니다.
