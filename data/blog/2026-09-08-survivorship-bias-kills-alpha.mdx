[지난 글](./2026-09-07-backtest-honest-attribution)의 마지막 문장은 이랬다.

> point-in-time 구성종목 데이터가 없으면 이 편향은 원리적으로 제거 불가능하다.

절반은 틀렸다. **구성종목 자체는 복원할 수 있었다.** 위키피디아 문서에 과거
리비전이 전부 남아 있기 때문이다.

그래서 해봤고, 결론이 뒤집혔다.

```
                          현재 구성종목      Point-in-Time
MaxSharpe(군집3)      연 23.63% / 0.95   연 14.48% / 0.61
동일가중(군집3)         연 21.22% / 0.84   연 12.17% / 0.51
동일가중(전체 유니버스)   연 14.70% / 0.63   연 13.48% / 0.59
SPY                  연 11.37% / 0.53   연 11.37% / 0.53
```

**연 9.15%p가 편향이었다.**

## 시점별 구성종목을 복원하는 법

위키피디아 API는 임의 시점의 리비전을 준다.

```python
def snapshot_members(ts):
    j = api({'action': 'query', 'prop': 'revisions',
             'titles': 'List of S&P 500 companies',
             'rvlimit': 1, 'rvdir': 'older', 'rvstart': ts,
             'rvprop': 'ids|timestamp', 'format': 'json'})
    revid = list(j['query']['pages'].values())[0]['revisions'][0]['revid']

    j2 = api({'action': 'parse', 'oldid': revid, 'prop': 'text',
              'format': 'json', 'formatversion': 2})
    for tbl in pd.read_html(io.StringIO(j2['parse']['text'])):
        cand = [c for c in map(str, tbl.columns)
                if re.search(r'(ticker|symbol)', c, re.I)]
        if cand and len(tbl) > 300:
            s = tbl[cand[0]].astype(str).str.replace('.', '-', regex=False)
            return sorted(set(s[s.str.match(r'^[A-Z][A-Z\-]{0,6}$')]))
```

컬럼명이 시기에 따라 `Ticker symbol` → `Symbol` 로 바뀌어서 정규식으로 잡았다.
2015-09 ~ 2023-09 의 97개 월말에 대해 돌렸고, **95개월을 직접 확보**했다
(2개월은 rate limit으로 실패, 직전 월로 보간 — 지수 구성은 월 단위로 거의 안 변한다).

2016년 스냅샷을 열어보니 `AA`(Alcoa), `ABC`(AmerisourceBergen), `CELG`(Celgene),
`ADS`, `AET` … 지금은 없는 이름들이 줄줄이 나왔다.

**기간 중 한 번이라도 S&P500에 있었던 종목은 704개.** 현재 리스트는 503개다.
**201개를 통째로 빠뜨리고 백테스트를 하고 있었다.**

## 그런데 여기서 벽을 만났다

704개를 다운로드했더니 **547개(77.7%)만 받아졌다.**

대표적인 퇴출 종목 20개를 따로 찍어봤다.

```
AA      2012행   2015-09-29 ~ 2023-09-26   (지수에서만 빠짐, 아직 상장)
AET      800행   2015-09-29 ~ 2018-11-29   (CVS 인수 시점까지)
ABC     없음     CELG 없음   BBBY 없음   CBS 없음   ADS 없음
AGN 없음  APC 없음  BHI 없음  BRCM 없음  CA 없음  FRC 없음
SIVB 없음  XLNX 없음  MYL 없음  ETFC 없음  TIF 없음  NBL 없음  WCG 없음

=> 20종목 중 2종목만 데이터 확보
```

**Yahoo Finance는 상장폐지 종목의 시세를 주지 않는다.** 티커를 알아도 소용없다.
인수합병으로 사라졌든 파산했든, 흔적이 없다.

그래서 편향이 사실 두 개였다는 걸 알게 됐다.

|                                               | 성격           | 고칠 수 있나                   |
| --------------------------------------------- | -------------- | ------------------------------ |
| 과거 유니버스에 **나중에 편입된 종목**이 섞임 | look-ahead     | **가능** — PIT 멤버십으로 제거 |
| **사라진 회사**가 데이터에 아예 없음          | 진짜 생존 편향 | **불가** — 크기 측정만         |

그동안 "생존 편향"이라고 뭉뚱그려 부르던 게 이렇게 나뉜다는 걸 몰랐다.
전자는 내가 2016년 유니버스에 2020년 편입된 종목을 넣고 있었다는 뜻이고,
이건 순수한 look-ahead다. 후자는 데이터 공급자의 문제다.

## 구멍의 크기를 재봤다

각 시점의 실제 구성종목 중 몇 %나 가격을 받을 수 있는지 세어봤다.

| 시점    | 실제 구성종목 | 가격 확보 | 누락    | 커버리지  |
| ------- | ------------- | --------- | ------- | --------- |
| 2015-09 | 505           | 307       | **198** | **60.8%** |
| 2017-04 | 505           | 338       | 167     | 66.9%     |
| 2018-11 | 505           | 364       | 141     | 72.1%     |
| 2020-05 | 505           | 397       | 108     | 78.6%     |

**과거로 갈수록 커버리지가 단조 감소한다.** 이게 생존 편향의 서명이다.
2015년에는 실제 지수의 **39%가 안 보인다.** 그리고 안 보이는 쪽은 무작위가
아니라 **망한 쪽에 치우쳐 있다.**

## 고칠 수 있는 것만 고쳤더니

look-ahead 부분만 제거했다. 각 월의 유니버스를 그 시점의 실제 구성종목으로 제한.

```python
mask = pd.Series([t in pit.get(d, set()) for d, t in data.index],
                 index=data.index)
data = data[mask]
```

한 줄이다. 그런데 결과가 이렇게 됐다.

- MaxSharpe 연 23.63% → **14.48%**, 샤프 0.95 → **0.61**
- 2020년 제외 시 전략 **9.69%** vs SPY 9.65% — 소수점까지 붙는다

그리고 가장 아팠던 건 이거다.

```
동일가중(전체 유니버스)   13.48%
동일가중(군집3)          12.17%   ← 클러스터링이 오히려 손해
```

**클러스터링이 아무것도 안 한 것보다 나쁘다.** 지난 글에서 "클러스터링의 몫
+6.52%p"라고 분해했던 게, 편향을 걷어내니 **-1.31%p**가 됐다.
남는 건 최대샤프 최적화의 +2.31%p뿐이다.

## 유의성을 물었어야 했다

여기서 한 가지를 더 깨달았다. 지난 글까지 나는 **"이겼다"만 봤지 "우연인가"를
한 번도 안 물었다.** 59개월짜리 표본이다.

월별 수익률에 Newey-West 보정(자기상관·이분산 robust) t-검정을 돌렸다.

|                   | 초과수익   | t        | p         | FF5 alpha     | p         |
| ----------------- | ---------- | -------- | --------- | ------------- | --------- |
| 현재 구성종목     | +0.936%/월 | 1.74     | 0.083     | +10.21%/년    | 0.061     |
| **Point-in-Time** | +0.256%/월 | **0.57** | **0.566** | **+2.97%/년** | **0.538** |

**p = 0.566.** 초과수익이 0이라는 가설을 전혀 기각하지 못한다.

주목할 건 편향을 안 걷은 버전도 p=0.083으로 **이미 5% 유의수준을 통과 못 했다**는
점이다. 나는 지난 글에서 "연 23.63%, 샤프 0.95"를 표에 적으면서 그게 통계적으로
유의하지 않다는 걸 확인조차 안 했다.

### Deflated Sharpe Ratio

여기에 데이터 스누핑 보정까지 걸었다. Bailey & López de Prado(2014)의
Deflated Sharpe Ratio는 "여러 번 시도해서 얻은 최고 성적"일 가능성을 할인한다.

```
PIT 기준, 관측 SR(월) 0.221
  시행  2회 가정 -> 기대 최대 SR 0.068 -> DSR 0.866
  시행 10회 가정 -> 기대 최대 SR 0.205 -> DSR 0.546
  시행 50회 가정 -> 기대 최대 SR 0.296 -> DSR 0.293
```

나는 피처 조합과 설정을 최소 10번은 바꿔봤다. 그러면 **DSR 0.55**.
0.95 근처는커녕 동전 던지기다.

## 정리

| 점검            | 결과                                 |
| --------------- | ------------------------------------ |
| 표면 성과       | 연 23.63%, 샤프 0.95                 |
| PIT 유니버스    | 연 14.48%, 샤프 0.61 (**-9.15%p**)   |
| 초과수익 유의성 | p = 0.566 (기각 실패)                |
| FF5 알파        | +2.97%/년, p = 0.538                 |
| Deflated Sharpe | 0.55 (10회 시행 가정)                |
| 클러스터링 기여 | **-1.31%p** (유니버스 동일가중 대비) |
| 2020년 제외     | 9.69% vs SPY 9.65%                   |

**알파는 없다.** 그리고 이건 코드가 틀려서가 아니다. 파이프라인은 처음부터
끝까지 정상 동작했다.

백테스트에서 제일 위험한 건 버그가 아니라 **맞게 돌아가면서 편향된 데이터를
먹는 코드**다. 버그는 에러를 내지만 편향은 그럴듯한 숫자를 낸다.

## CFA 관점에서

Level II Portfolio Management의 `Backtesting and Simulation` 모듈,
"identify problems in a backtest of an investment strategy" LOS가
survivorship bias / look-ahead bias / data snooping 셋을 나열한다.

교재에서 읽을 때는 세 개가 나란한 항목으로 보였는데, 직접 부딪히니 층위가 달랐다.

- **look-ahead** — 코드로 고칠 수 있다. `expanding()`, 베타 시프트, PIT 멤버십.
- **survivorship** — 데이터를 사야 고칠 수 있다. 코드로는 크기만 잰다.
- **data snooping** — 고치는 게 아니라 **할인하는** 것이다. DSR이 그 도구다.

그리고 교재가 안 알려준 것: **생존 편향은 "성과가 조금 부풀려진다" 수준이
아니라 결론을 뒤집는다.** 14.48% vs 23.63%는 정도의 차이가 아니라
"쓸 수 있다 / 없다"의 차이다.
