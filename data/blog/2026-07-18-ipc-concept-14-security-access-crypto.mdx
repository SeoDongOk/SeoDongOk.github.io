## 시험 직전 빈출도

> **우선순위 S · ★★★★★**
>
> 접근통제는 2020·2023·2025년 출제 이력이 표시되고 암호·해시와 함께 반복된다.

- **최소 암기:** CIA, DAC·MAC·RBAC, 대칭키·비대칭키·해시, 전자서명
- **5점 후보:** DAC=소유자 / MAC=보안등급·시스템 / RBAC=역할·중앙관리자
- **판정 기준:** 별점은 Q-Net의 공식 출제 확률이 아니다. 2020년 1회~2026년 1회 복원 목록과 2026 시나공 핵심요약의 실기 출제 이력 표기를 개념군 단위로 교차해 정한 **시험 전날 상대 우선순위**다.

보안 이론은 비슷한 목적의 용어를 구분해야 한다. **인증은 신원 확인**, **인가는 권한 결정**, **암호화는 기밀성**, **해시는 무결성**이라는 축을 먼저 잡는다.

## 1. CIA 3요소

| 요소   | 의미                              | 대표 위협      |
| ------ | --------------------------------- | -------------- |
| 기밀성 | 인가된 사용자만 정보 접근         | 도청·정보 유출 |
| 무결성 | 정보가 허가 없이 변경되지 않음    | 위변조         |
| 가용성 | 필요할 때 서비스와 정보 사용 가능 | 서비스 거부    |

```text
노출 방지 = 기밀성
변조 방지 = 무결성
중단 방지 = 가용성
```

## 2. 추가 보안 속성

| 속성        | 의미                                   |
| ----------- | -------------------------------------- |
| 인증        | 사용자·시스템의 신원 확인              |
| 인가        | 인증된 주체가 수행할 수 있는 권한 결정 |
| 책임 추적성 | 행위를 특정 주체와 연결해 추적 가능    |
| 부인 방지   | 행위 사실을 나중에 부인하지 못하게 함  |

## 3. 인증 요소

| 요소      | 예시                           |
| --------- | ------------------------------ |
| 지식 기반 | 비밀번호, PIN                  |
| 소유 기반 | OTP 토큰, 스마트카드, 휴대전화 |
| 생체 기반 | 지문, 얼굴, 홍채               |
| 위치 기반 | 접속 위치, 네트워크 위치       |
| 행위 기반 | 서명 습관, 키보드 입력 패턴    |

둘 이상의 서로 다른 요소를 결합하면 다중요소 인증이다.

## 4. 접근 통제 구성

```text
식별: 사용자가 누구인지 주장
인증: 그 주장이 맞는지 확인
인가: 허용할 작업 결정
감사: 수행한 작업 기록과 추적
```

## 5. DAC, MAC, RBAC

| 모델 | 기준           | 핵심                       |
| ---- | -------------- | -------------------------- |
| DAC  | 소유자·신분    | 자원 소유자가 권한 부여    |
| MAC  | 보안 등급·규칙 | 중앙 정책에 따라 강제 통제 |
| RBAC | 조직의 역할    | 직무·역할에 권한 부여      |

```text
소유자 = DAC
등급·규칙 = MAC
역할·직무 = RBAC
```

## 6. 최소 권한과 직무 분리

| 원칙      | 의미                                 |
| --------- | ------------------------------------ |
| 최소 권한 | 업무에 필요한 최소 권한만 부여       |
| 직무 분리 | 중요한 업무를 여러 사람·역할로 분리  |
| 기본 거부 | 명시적으로 허용하지 않은 접근은 거부 |

## 7. 대칭키 암호

암호화와 복호화에 같은 키를 사용한다.

```text
속도가 빠름
대용량 데이터 암호화에 적합
키 배송과 키 관리가 어려움
```

대표 알고리즘:

```text
DES, 3DES, AES, SEED, ARIA
```

## 8. 공개키 암호

공개키와 개인키의 쌍을 사용한다.

```text
키 배포가 상대적으로 쉬움
대칭키보다 연산이 느림
암호화·전자서명·키 교환에 활용
```

대표 알고리즘:

```text
RSA, ECC, ElGamal
```

## 9. 해시 함수

임의 길이 입력을 고정 길이 값으로 변환하는 단방향 함수다.

```text
역연산이 어려움
같은 입력은 같은 해시
입력이 조금만 바뀌어도 결과가 크게 달라짐
무결성 검증과 비밀번호 저장에 활용
```

대표 알고리즘:

```text
SHA-2, SHA-3
MD5와 SHA-1은 충돌 취약성 때문에 보안 용도로 권장되지 않음
```

## 10. 기밀성과 전자서명

### 기밀성

```text
수신자의 공개키로 암호화
→ 수신자의 개인키로 복호화
```

### 전자서명

```text
송신자의 개인키로 서명
→ 송신자의 공개키로 검증
```

전자서명은 무결성, 인증, 부인 방지를 제공한다. 기밀성 자체를 제공하는 것은 아니다.

## 11. MAC과 전자서명

| 구분      | 메시지 인증 코드(MAC) | 전자서명              |
| --------- | --------------------- | --------------------- |
| 키        | 공유 비밀키           | 공개키·개인키         |
| 제공      | 무결성·인증           | 무결성·인증·부인 방지 |
| 부인 방지 | 제공하지 못함         | 제공 가능             |

## 12. 인증·인가 표준

| 기술  | 핵심                                        |
| ----- | ------------------------------------------- |
| OAuth | 비밀번호 공유 없이 제3자에게 접근 권한 위임 |
| OIDC  | OAuth 2.0 위에 사용자 인증 계층 추가        |
| SAML  | XML 기반 인증·인가 정보 교환                |
| SSO   | 한 번 인증해 여러 연계 서비스 이용          |
| JWT   | 서명된 클레임을 담는 토큰 형식              |

```text
권한 위임 = OAuth
OAuth 기반 로그인·인증 = OIDC
한 번 로그인 = SSO
```

## 13. TLS와 VPN

| 기술  | 의미                                     |
| ----- | ---------------------------------------- |
| TLS   | 통신 구간의 기밀성·무결성·서버 인증 제공 |
| VPN   | 공용망 위에 암호화된 사설 통신 경로 구성 |
| IPSec | IP 계층에서 인증·무결성·암호화 제공      |

IPSec의 AH는 인증과 무결성, ESP는 암호화를 포함한 기밀성을 제공한다.

## 14. 시험 직전 암기

```text
CIA = 기밀성·무결성·가용성
인증 = 누구인가
인가 = 무엇을 할 수 있는가
DAC = 소유자
MAC = 등급·강제
RBAC = 역할
대칭키 = 같은 키·빠름
공개키 = 키 쌍·느림
해시 = 단방향·무결성
기밀성 = 수신자 공개키
전자서명 = 송신자 개인키
OAuth = 권한 위임
OIDC = 인증
```
