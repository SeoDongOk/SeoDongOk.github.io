## 시험 직전 빈출도

> **우선순위 S · ★★★★★**
>
> 테스트 원리·화이트박스/블랙박스·조건/결정 커버리지가 반복 출제된 핵심 영역이다.

- **최소 암기:** 살충제 패러독스, 오류-부재의 궤변, 문장·결정·조건·조건/결정 커버리지 차이
- **5점 후보:** 결정은 전체 분기 결과 T/F, 조건은 각 개별 조건 T/F
- **판정 기준:** 별점은 Q-Net의 공식 출제 확률이 아니다. 2020년 1회~2026년 1회 복원 목록과 2026 시나공 핵심요약의 실기 출제 이력 표기를 개념군 단위로 교차해 정한 **시험 전날 상대 우선순위**다.

테스트 영역은 비슷한 정의를 비교하는 문제가 많다. 특히 **문장·결정·조건 커버리지**와 **동등 분할·경곗값 분석**을 설명만 보고 구분할 수 있어야 한다.

## 1. 테스트 기본 원리

| 원리                 | 의미                                        |
| -------------------- | ------------------------------------------- |
| 완벽한 테스트 불가능 | 모든 입력과 경로를 전부 검사할 수 없음      |
| 결함 집중            | 소수 모듈에서 대부분의 결함 발견            |
| 파레토 법칙          | 약 20% 코드에서 약 80% 결함 발견            |
| 살충제 패러독스      | 같은 테스트 반복 시 새 결함 발견이 어려워짐 |
| 정황 의존            | 시스템 특성에 따라 테스트 방법이 달라짐     |
| 오류-부재의 궤변     | 결함이 없어도 요구 미충족이면 품질이 낮음   |
| 조기 테스트          | 개발 초기에 결함을 찾을수록 수정 비용 감소  |

## 2. Verification과 Validation

```text
Verification: 제품을 올바르게 만들고 있는가?
Validation: 올바른 제품을 만들고 있는가?
```

- Verification은 명세와 설계에 맞게 구현되는지 확인한다.
- Validation은 최종 제품이 사용자 요구를 충족하는지 확인한다.

## 3. 정적 테스트와 동적 테스트

| 구분      | 정적 테스트                  | 동적 테스트          |
| --------- | ---------------------------- | -------------------- |
| 실행 여부 | 프로그램을 실행하지 않음     | 프로그램을 실행함    |
| 대상      | 명세서, 설계서, 소스 코드    | 실행 가능한 프로그램 |
| 예시      | 동료검토, 워크스루, 인스펙션 | 화이트박스, 블랙박스 |

## 4. 화이트박스 테스트

프로그램의 내부 구조와 제어 흐름을 기준으로 테스트한다.

| 기법             | 핵심                              |
| ---------------- | --------------------------------- |
| 기초 경로 검사   | 제어 흐름 그래프의 독립 경로 검사 |
| 조건 검사        | 논리 조건의 참·거짓 검사          |
| 루프 검사        | 반복문의 시작·종료·횟수 검사      |
| 데이터 흐름 검사 | 변수 정의와 사용 위치 검사        |

### 순환 복잡도

독립적인 실행 경로의 수를 나타낸다.

```text
V(G) = 간선 수 - 노드 수 + 2
V(G) = 조건 노드 수 + 1
```

## 5. 테스트 커버리지

| 커버리지           | 만족 조건                                      |
| ------------------ | ---------------------------------------------- |
| 문장 커버리지      | 모든 실행문을 한 번 이상 실행                  |
| 결정·분기 커버리지 | 전체 결정식의 참·거짓을 모두 실행              |
| 조건 커버리지      | 결정식 내부 각 개별 조건의 참·거짓을 모두 실행 |
| 조건/결정 커버리지 | 개별 조건과 전체 결정 결과 모두 참·거짓 실행   |
| MC/DC              | 각 개별 조건이 전체 결정에 독립적으로 영향     |
| 다중 조건 커버리지 | 개별 조건의 가능한 모든 조합 실행              |

### 구분 예제

```text
if (A || B) execute();
```

- 문장: `execute()`가 한 번 이상 실행
- 결정: `A || B` 전체가 참인 경우와 거짓인 경우 실행
- 조건: A와 B 각각이 참·거짓인 경우 실행
- 다중 조건: TT, TF, FT, FF 모든 조합 실행

```text
실행문 → 문장
전체 판단 결과 → 결정
판단문 속 개별식 → 조건
모든 조합 → 다중 조건
```

## 6. 블랙박스 테스트

내부 코드를 보지 않고 입력과 출력 명세를 기준으로 검사한다.

| 기법             | 핵심                                              |
| ---------------- | ------------------------------------------------- |
| 동등 분할        | 입력 영역을 유효·무효 그룹으로 나누어 대표값 선택 |
| 경곗값 분석      | 경계와 경계 바로 전·후 검사                       |
| 결정 테이블      | 조건과 행동의 조합을 표로 검사                    |
| 상태 전이        | 이벤트에 따른 상태 변화 검사                      |
| 원인-효과 그래프 | 입력 조건과 출력 결과의 관계 분석                 |
| 오류 추정        | 경험으로 오류 가능성이 높은 부분 검사             |
| 비교 검사        | 여러 버전의 같은 결과를 비교                      |

### 경곗값 예제

허용 범위가 20~60이라면 대표 경곗값은 다음과 같다.

```text
19, 20, 21, 59, 60, 61
```

## 7. 테스트 단계

| 단계          | 대상                            |
| ------------- | ------------------------------- |
| 단위 테스트   | 함수·클래스·모듈 등 최소 단위   |
| 통합 테스트   | 모듈 사이 인터페이스와 상호작용 |
| 시스템 테스트 | 완성된 전체 시스템              |
| 인수 테스트   | 사용자 요구 충족 여부           |

## 8. 인수 테스트

| 유형               | 의미                                      |
| ------------------ | ----------------------------------------- |
| 알파 테스트        | 개발자 환경에서 사용자가 수행             |
| 베타 테스트        | 실제 사용자 환경에서 제한된 사용자가 수행 |
| 사용자 인수 테스트 | 실제 사용자가 업무 요구 충족 확인         |
| 운영 인수 테스트   | 백업·복구·보안·운영 절차 확인             |

## 9. 결함 생명주기

```text
결함 등록 → 검토 → 할당 → 수정 → 재테스트 → 종료
```

수정 후 기존 기능에 문제가 생기지 않았는지 확인하는 테스트는 회귀 테스트다.

## 10. 시험 직전 암기

```text
같은 테스트 반복 = 살충제 패러독스
소수 모듈에 결함 집중 = 결함 집중
요구 미충족 = 오류-부재의 궤변
실행하지 않음 = 정적 테스트
내부 구조 = 화이트박스
입출력 명세 = 블랙박스
실행문 = 문장 커버리지
전체 참·거짓 = 결정 커버리지
개별 조건 참·거짓 = 조건 커버리지
대표 그룹 = 동등 분할
경계 전후 = 경곗값 분석
수정 후 재검사 = 회귀 테스트
```
