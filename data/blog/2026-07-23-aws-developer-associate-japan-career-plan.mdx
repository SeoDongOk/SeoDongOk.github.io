정보처리기사 실기 시험을 마치고 다음 목표를 정했다. 2026년 8월 말까지 **AWS Certified Developer - Associate**에 도전한다.

이번 자격증의 목적은 단순히 이력서에 한 줄을 추가하는 것이 아니다. 2027년 4월 일본 취업을 준비하면서 내가 이미 해 온 AWS 배포·운영 경험을 체계적으로 정리하고, 일본 금융·핀테크 기업에 보여 줄 수 있는 하나의 객관적인 증거로 만드는 것이 목표다.

## 왜 지금 AWS 자격증인가

내가 목표로 하는 직무는 다음과 같다.

- 일본의 백엔드·풀스택 엔지니어
- FX·증권·핀테크 플랫폼 개발자
- 외부 금융기관 API와 비동기 트랜잭션을 다루는 소프트웨어 엔지니어

현재 주력 기술은 Node.js, NestJS, TypeScript, Python, MySQL·MariaDB, Docker, Jenkins, React·Next.js 그리고 AWS다. 실무에서는 외부 파트너 API 연동, 중복 요청 방지, 실패 요청 재처리, 상태 기반 워크플로, 데이터 정합성 검증, 장애 분석과 AWS 배포를 경험했다.

하지만 이 경험을 채용 담당자가 짧은 이력서만 보고 정확히 판단하기는 어렵다. AWS 자격증은 실무 경험 자체를 대신하지는 못하지만 다음 세 가지를 보완할 수 있다.

1. AWS 서비스를 단편적으로 사용한 것이 아니라 개발·보안·배포·장애 대응의 구조로 이해하고 있음을 보여 준다.
2. 일본 채용 공고에서 자주 등장하는 AWS 역량을 검색 가능한 키워드로 명확하게 만든다.
3. 면접에서 경험을 설명할 때 AWS의 표준 용어와 모범 사례로 답변할 수 있게 한다.

따라서 이번 도전의 공식은 **자격증 + 실습 프로젝트 + 일본어 면접 설명**이다. 합격증만 얻고 끝내지 않는다.

## Developer Associate를 선택한 이유

AWS에는 여러 자격증이 있지만 첫 목표로 **AWS Certified Developer - Associate(DVA-C02)**를 선택했다.

[AWS 공식 시험 안내](https://aws.amazon.com/certification/certified-developer-associate/)에 따르면 이 자격증은 AWS 기반 애플리케이션의 개발, 테스트, 배포, 디버깅 역량을 검증한다. AWS 서비스로 애플리케이션을 개발하고 CI/CD로 배포하며, 보안과 장애 해결까지 다룬다는 점에서 현재 업무와 목표 직무에 가장 가깝다.

Solutions Architect Associate가 분산 시스템의 설계 판단을 폭넓게 다룬다면, Developer Associate는 코드와 애플리케이션 수명주기에 더 직접적으로 연결된다. 이미 백엔드 개발자로 일하고 있는 나에게는 Developer Associate로 실무 지식을 먼저 단단하게 만든 뒤, 필요하면 Solutions Architect나 DevOps Engineer로 확장하는 순서가 효율적이라고 판단했다.

## 2026년 7월 기준 시험 정보

시험을 준비하기 전에 반드시 최신 공식 안내를 기준으로 범위를 고정해야 한다. 현재 시험 코드는 **DVA-C02**다.

| 항목          | 내용                                     |
| ------------- | ---------------------------------------- |
| 등급          | Associate                                |
| 시험 시간     | 130분                                    |
| 문항 수       | 65문항                                   |
| 문제 형식     | 객관식·복수 응답                         |
| 응시료        | 150달러                                  |
| 응시 방법     | Pearson VUE 시험장 또는 온라인 감독 시험 |
| 지원 언어     | 한국어·일본어·영어 등                    |
| 자격 유효기간 | 3년                                      |

공식 시험 가이드에는 65문항 중 **50문항이 채점 대상이고 15문항은 비채점 문항**이며, 합격 기준은 100~1,000점 환산 점수 중 **720점**이라고 명시되어 있다. 비채점 문항은 시험 중 따로 표시되지 않으므로 모든 문제를 같은 비중으로 풀어야 한다. 자세한 기준은 [AWS DVA-C02 공식 시험 가이드](https://docs.aws.amazon.com/aws-certification/latest/developer-associate-02/developer-associate-02.html)에서 확인할 수 있다.

## 출제 영역과 공부 우선순위

공식 가이드의 영역별 비중은 다음과 같다.

| 영역                     | 비중 | 나의 우선순위 |
| ------------------------ | ---: | ------------- |
| AWS 서비스를 사용한 개발 |  32% | 최우선        |
| 보안                     |  26% | 최우선        |
| 배포                     |  24% | 높음          |
| 문제 해결과 최적화       |  18% | 높음          |

### 1. AWS 서비스를 사용한 개발 — 32%

가장 큰 영역이다. 단순히 서비스 이름을 외우기보다 **어떤 요구사항에서 어떤 서비스를 조합하는지**를 판단해야 한다.

- Lambda 실행 모델, 동시성, 버전과 별칭
- API Gateway 연동과 인증
- DynamoDB 파티션 키, 인덱스, 일관성, 조건부 쓰기
- S3 객체 처리와 이벤트 기반 개발
- SQS·SNS·EventBridge를 이용한 비동기 처리
- Step Functions를 이용한 상태 기반 워크플로
- AWS SDK의 재시도, 페이지네이션, 오류 처리

특히 멱등성, 중복 처리 방지, 실패 재시도는 내가 실무에서 다룬 주제다. 기존 경험을 Lambda, SQS, DynamoDB 조건부 쓰기, DLQ와 연결해 설명할 수 있도록 정리한다.

### 2. 보안 — 26%

금융 플랫폼을 목표로 한다면 시험 합격 여부와 관계없이 반드시 깊게 공부해야 하는 영역이다.

- IAM 사용자·그룹·역할·정책의 차이
- 최소 권한 원칙과 리소스 기반 정책
- STS 임시 자격 증명
- Cognito 인증·인가
- KMS 암호화와 키 정책
- Secrets Manager와 Systems Manager Parameter Store
- 전송 중·저장 시 암호화

애플리케이션에 액세스 키를 하드코딩하지 않고 역할과 임시 자격 증명을 사용해야 하는 이유까지 설명할 수 있어야 한다. 공식 범위는 [DVA-C02 보안 영역](https://docs.aws.amazon.com/aws-certification/latest/developer-associate-02/developer-associate-02-domain2.html)에 정리되어 있다.

### 3. 배포 — 24%

Jenkins와 Docker, AWS 배포 경험을 AWS 네이티브 CI/CD 개념으로 확장한다.

- CodeBuild·CodeDeploy·CodePipeline의 역할
- SAM·CloudFormation을 이용한 배포
- Lambda 버전·별칭과 트래픽 전환
- 블루/그린, 카나리, 롤링 배포
- 환경 변수와 애플리케이션 설정 분리
- 배포 실패 시 롤백과 테스트 자동화

공식 가이드는 패키징, 개발 환경 테스트, 자동화된 배포 테스트, CI/CD를 주요 과제로 제시한다. 세부 항목은 [DVA-C02 배포 영역](https://docs.aws.amazon.com/aws-certification/latest/developer-associate-02/developer-associate-02-domain3.html)을 기준으로 체크한다.

### 4. 문제 해결과 최적화 — 18%

단순한 로그 확인이 아니라 장애 원인을 좁히고 성능과 비용을 개선하는 판단이 중요하다.

- CloudWatch Logs·Metrics·Alarms
- X-Ray 분산 추적
- Lambda 메모리·실행 시간·콜드 스타트 최적화
- 비동기 호출 실패와 DLQ 분석
- API·데이터베이스 병목 분석
- 캐시와 동시성 제어

이 영역은 기존 장애 대응 경험을 가장 잘 활용할 수 있다. 문제 상황, 관측 데이터, 원인, 조치, 재발 방지의 순서로 사례를 정리한다. 공식 과제는 [DVA-C02 문제 해결 및 최적화 영역](https://docs.aws.amazon.com/aws-certification/latest/developer-associate-02/developer-associate-02-domain4.html)에서 확인한다.

## 한 달 크러시 코스

목표 응시 시점은 2026년 8월 말이다. 학습 기간은 약 5주로 잡는다.

### 1주 차 — 진단과 서버리스 기본기

- 공식 시험 가이드 전체 읽기
- 진단 문제로 취약 영역 확인
- Lambda, API Gateway, DynamoDB 집중 학습
- 매일 오답을 `서비스 선택 기준 / 틀린 이유 / 반례` 형식으로 기록

### 2주 차 — 이벤트 기반 아키텍처와 보안

- SQS, SNS, EventBridge, Step Functions 비교
- 재시도, 가시성 제한 시간, DLQ, 멱등성 정리
- IAM, STS, Cognito, KMS 집중 학습
- 정책 평가 문제는 명시적 거부부터 추적하는 습관 만들기

### 3주 차 — 배포와 관측 가능성

- CodePipeline, CodeBuild, CodeDeploy 역할 구분
- SAM·CloudFormation 기본 템플릿 작성
- CloudWatch와 X-Ray로 오류 추적
- 카나리·블루/그린 배포 시나리오 비교

### 4주 차 — 문제 풀이와 약점 보강

- 영역별 문제를 시간 제한 없이 정확하게 풀이
- 틀린 선택지까지 왜 틀렸는지 설명
- 비슷한 서비스의 선택 기준을 한 장 표로 압축
- 공식 연습 문제 세트로 출제 문장에 적응

### 5주 차 — 실전 모의고사와 최종 정리

- 65문항, 130분 조건으로 모의고사 진행
- 연속 모의고사에서 안정적인 합격권 점수 확보
- 마지막 3일은 새 강의보다 오답과 공식 문서만 복습
- 시험 하루 전에는 IAM, Lambda, DynamoDB, SQS, 배포 전략만 압축 회독

AWS도 시험 준비 단계로 시험 가이드 검토, 공식 연습 문제 세트, 부족한 영역의 디지털 교육·실습, 공식 연습 시험을 안내한다. 준비 자료는 [AWS 공식 시험 준비 페이지](https://aws.amazon.com/certification/certified-developer-associate/)를 기준으로 선택한다.

## 자격증을 포트폴리오로 바꾸는 실습

시험 공부와 별도로 작은 금융 트랜잭션 처리 시스템을 만든다.

```text
API Gateway
  → Lambda 요청 검증
  → DynamoDB 멱등성 키 확인
  → SQS 비동기 작업 전달
  → Lambda 처리
  → 실패 시 DLQ
  → CloudWatch 경보와 X-Ray 추적
```

핵심 요구사항은 다음과 같다.

1. 같은 거래 요청이 여러 번 도착해도 한 번만 처리한다.
2. 외부기관 호출 실패 시 지수 백오프로 재시도한다.
3. 재시도 한도를 초과한 요청은 DLQ로 격리한다.
4. 민감한 설정은 Secrets Manager 또는 Parameter Store에서 관리한다.
5. IAM 역할은 최소 권한으로 분리한다.
6. SAM 또는 CloudFormation으로 인프라를 재현한다.
7. CloudWatch 대시보드에서 성공률과 실패율을 확인한다.

이 프로젝트는 시험 서비스를 억지로 모두 넣기 위한 것이 아니다. 일본 금융회사에 내가 설명하고 싶은 **멱등성, 데이터 정합성, 장애 복구, 관측 가능성, 보안**을 하나의 실행 가능한 사례로 묶는 것이 목적이다.

## 일본 취업 서류와 면접에 연결하는 방법

자격증 취득 후 이력서에는 자격증 이름만 적지 않는다. 실무와 프로젝트를 함께 연결한다.

### 한국어 표현

> AWS 기반 비동기 트랜잭션 처리 시스템을 설계하고, 멱등성 제어·재시도·DLQ·모니터링을 구현했습니다. AWS Certified Developer - Associate 학습을 통해 보안, 배포, 장애 대응 지식을 체계화했습니다.

### 일본어 표현

> AWS上で非同期トランザクション処理システムを設計し、冪等性制御、リトライ、DLQ、モニタリングを実装しました。AWS Certified Developer - Associateの学習を通じて、セキュリティ、デプロイ、障害対応の知識を体系化しました。

면접에서는 다음 네 가지를 반드시 설명할 수 있도록 준비한다.

- 왜 해당 AWS 서비스를 선택했는가
- 다른 대안과 비교했을 때 어떤 장단점이 있는가
- 실패와 중복을 어떻게 처리했는가
- 로그와 지표로 장애 원인을 어떻게 찾았는가

## 합격보다 중요한 완료 기준

이번 목표의 완료 조건은 시험 합격 한 가지가 아니다.

- [ ] DVA-C02 합격
- [ ] 공식 시험 범위 기준 오답 노트 완성
- [ ] 서버리스 금융 트랜잭션 실습 프로젝트 공개
- [ ] 아키텍처 다이어그램과 README 작성
- [ ] 일본어 이력서에 넣을 AWS 경력 문장 완성
- [ ] 장애 대응 사례를 STAR 방식으로 설명 가능

자격증만으로 일본 취업이 보장되지는 않는다. 그러나 실무 경험을 구조화하고, 부족한 보안·CI/CD·관측 가능성 지식을 채우며, 결과물을 일본어로 설명할 수 있다면 자격증은 분명한 증폭기가 된다.

정보처리기사 실기가 국내 경력의 기본기를 보완하는 단계였다면, AWS Developer Associate는 일본의 금융·핀테크 개발자 채용에 맞춰 클라우드 개발 역량을 증명하는 첫 단계다. 이번에는 합격증에서 끝내지 않고 **실제로 설계하고 설명할 수 있는 AWS 개발자**가 되는 데까지 진행한다.
