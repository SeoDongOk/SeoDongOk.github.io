## 시험 직전 빈출도

> **우선순위 A · ★★★★☆**
>
> XML·JSON·SOAP·REST·EAI/ESB는 2020년 이후 인터페이스 구현 단답형으로 꾸준히 교차 출제됐다.

- **최소 암기:** EAI·ESB·MOM·RPC, XML·JSON·YAML, SOAP·REST
- **5점 후보:** SOAP=XML·WSDL·무거움 / REST=HTTP 메서드·자원 URI·무상태 / ESB=버스형 중앙 연계
- **판정 기준:** 별점은 Q-Net의 공식 출제 확률이 아니다. 2020년 1회~2026년 1회 복원 목록과 2026 시나공 핵심요약의 실기 출제 이력 표기를 개념군 단위로 교차해 정한 **시험 전날 상대 우선순위**다.

인터페이스 문제는 시스템 사이의 연결 방식과 데이터 교환 형식을 묻는다. EAI와 ESB, SOAP과 REST, XML과 JSON의 차이를 중심으로 학습한다.

## 1. 인터페이스

서로 다른 시스템·컴포넌트가 데이터와 기능을 주고받기 위해 정의한 접점과 규칙이다.

```text
송신 시스템
인터페이스
수신 시스템
```

### 명세 요소

```text
인터페이스 이름과 목적
송신·수신 시스템
데이터 항목과 형식
통신 방식과 주기
오류 코드와 예외 처리
보안과 권한
타임아웃과 재시도
```

## 2. 연계 방식

| 구분 | 직접 연계                    | 간접 연계                   |
| ---- | ---------------------------- | --------------------------- |
| 방식 | 시스템끼리 직접 연결         | 중간 솔루션·미들웨어 사용   |
| 장점 | 단순하고 성능이 좋을 수 있음 | 결합도 감소, 확장·관리 용이 |
| 단점 | 시스템 수 증가 시 연결 복잡  | 중간 계층 운영 비용 발생    |

## 3. 동기와 비동기

| 방식   | 의미                                            |
| ------ | ----------------------------------------------- |
| 동기   | 요청 후 응답을 받을 때까지 대기                 |
| 비동기 | 요청 후 다른 작업을 수행하고 결과를 나중에 처리 |

```text
즉시 응답 필요·강한 순서 의존 = 동기
대량 처리·느슨한 결합·버퍼링 = 비동기
```

## 4. 미들웨어

서로 다른 운영체제·응용 프로그램·프로토콜 사이의 통신과 데이터 교환을 지원하는 중간 소프트웨어다.

| 유형       | 역할                                  |
| ---------- | ------------------------------------- |
| RPC        | 원격 프로시저를 로컬 함수처럼 호출    |
| MOM        | 메시지 큐 기반 비동기 통신            |
| ORB        | 분산 객체 사이의 통신 지원            |
| TP Monitor | 다수 트랜잭션의 분산 처리와 부하 관리 |
| WAS        | 웹 애플리케이션 실행 환경 제공        |

## 5. EAI

기업 내부의 여러 애플리케이션을 통합하는 솔루션이다.

| 구성           | 의미                           |
| -------------- | ------------------------------ |
| Point-to-Point | 시스템을 1:1로 직접 연결       |
| Hub & Spoke    | 중앙 허브를 통해 시스템 연결   |
| Message Bus    | 공통 버스를 통해 연결          |
| Hybrid         | Hub & Spoke와 Message Bus 혼합 |

```text
1:1 연결 증가로 복잡 = Point-to-Point
중앙 집중 = Hub & Spoke
공통 버스 = Message Bus
```

## 6. ESB

서비스 중심으로 시스템을 연결하는 버스형 미들웨어다.

```text
서비스 라우팅
메시지 변환
프로토콜 변환
보안과 모니터링
느슨한 결합
```

EAI가 기업 내부 애플리케이션 통합에 초점을 두는 반면 ESB는 서비스 중심의 유연한 통합을 강조한다.

## 7. XML

사용자가 태그를 정의할 수 있는 확장 가능한 마크업 언어다.

```text
계층 구조
스키마를 통한 검증
네임스페이스 지원
태그 때문에 데이터 크기가 큼
```

| 관련 기술 | 역할                          |
| --------- | ----------------------------- |
| XSD       | XML 문서 구조와 자료형 정의   |
| DTD       | XML 문서 구조 정의            |
| XPath     | XML 노드 선택                 |
| XSLT      | XML 문서를 다른 형식으로 변환 |

## 8. JSON

키-값과 배열로 데이터를 표현하는 경량 데이터 형식이다.

```text
사람과 프로그램이 읽기 쉬움
웹 API에서 널리 사용
XML보다 일반적으로 간결
주석은 표준 JSON에서 지원하지 않음
```

## 9. YAML

들여쓰기를 이용해 계층 구조를 표현하는 사람이 읽기 쉬운 데이터 직렬화 형식이다.

```text
설정 파일에 자주 사용
들여쓰기 중요
앵커와 별칭 지원
```

## 10. SOAP

XML 기반 메시지와 엄격한 표준을 사용하는 웹 서비스 방식이다.

```text
XML 메시지
WSDL로 서비스 명세
WS-Security 등 확장 표준
규격이 엄격하고 메시지가 무거움
```

## 11. REST

자원을 URI로 표현하고 HTTP 메서드로 상태를 전송하는 아키텍처 스타일이다.

### 제약 조건

```text
클라이언트-서버
무상태성
캐시 가능
균일한 인터페이스
계층형 시스템
선택적 코드 전송
```

### HTTP 메서드 의미

| 메서드 | 일반적 목적         |
| ------ | ------------------- |
| GET    | 자원 조회           |
| POST   | 자원 생성·처리 요청 |
| PUT    | 자원 전체 교체      |
| PATCH  | 자원 일부 수정      |
| DELETE | 자원 삭제           |

## 14. 시험 직전 암기

```text
원격 함수를 로컬처럼 = RPC
메시지 큐 = MOM
중앙 허브 = Hub & Spoke
공통 버스 = Message Bus
서비스 중심 버스 = ESB
태그 기반 = XML
경량 키-값 = JSON
들여쓰기 설정 = YAML
XML·WSDL = SOAP
URI·HTTP·무상태 = REST
요청 후 대기 = 동기
나중에 결과 처리 = 비동기
```
