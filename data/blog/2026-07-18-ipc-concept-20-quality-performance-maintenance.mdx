## 시험 직전 빈출도

> **우선순위 B · ★★★☆☆**
>
> 품질 특성·유지보수는 출제기준 범위이지만 세부 항목이 넓어 핵심군 학습 후 보는 편이 효율적이다.

- **최소 암기:** ISO 25010 8특성, 처리량·응답/반환 시간, 유지보수 4유형, MTBF·MTTR·가용성
- **5점 후보:** 유지보수=수정·적응·완전·예방 / 가용성=MTBF÷(MTBF+MTTR)
- **판정 기준:** 별점은 Q-Net의 공식 출제 확률이 아니다. 2020년 1회~2026년 1회 복원 목록과 2026 시나공 핵심요약의 실기 출제 이력 표기를 개념군 단위로 교차해 정한 **시험 전날 상대 우선순위**다.

마지막 핵심 영역은 소프트웨어가 요구 기능을 얼마나 안정적이고 효율적으로 제공하는지 평가하는 품질과 성능이다. `응답 시작`, `전체 처리 완료`, `단위 시간 처리량`을 구분한다.

## 1. 소프트웨어 품질

명시된 요구사항과 사용자의 기대를 만족하는 소프트웨어의 특성 전체를 의미한다.

```text
기능 충족
신뢰성
사용 편의성
성능 효율
유지보수와 이식 용이성
보안과 호환성
```

## 2. ISO/IEC 25010 품질 특성

| 특성        | 의미                                   |
| ----------- | -------------------------------------- |
| 기능 적합성 | 요구 기능을 정확하고 완전하게 제공     |
| 성능 효율성 | 시간·자원을 효율적으로 사용            |
| 호환성      | 다른 시스템과 공존·상호운용            |
| 사용성      | 사용자가 이해하고 배우고 조작하기 쉬움 |
| 신뢰성      | 정해진 조건에서 기능을 안정적으로 수행 |
| 보안성      | 정보와 시스템을 보호                   |
| 유지보수성  | 분석·수정·테스트가 쉬움                |
| 이식성      | 다른 환경으로 이전·설치가 쉬움         |

## 3. 품질 특성 식별어

```text
요구 기능 충족 = 기능 적합성
응답 시간·자원 사용 = 성능 효율성
다른 시스템과 연동 = 호환성
배우고 사용하기 쉬움 = 사용성
장애 없이 동작·복구 = 신뢰성
기밀성·무결성 = 보안성
수정·분석·테스트 용이 = 유지보수성
다른 환경에 설치 = 이식성
```

## 4. 애플리케이션 성능 지표

| 지표                       | 의미                                      |
| -------------------------- | ----------------------------------------- |
| 처리량(Throughput)         | 단위 시간에 처리한 작업·트랜잭션 수       |
| 응답 시간(Response Time)   | 요청 후 응답이 시작될 때까지의 시간       |
| 경과 시간(Turnaround Time) | 요청부터 전체 처리가 완료될 때까지의 시간 |
| 자원 사용률                | CPU, 메모리, 네트워크, 디스크 사용량      |

```text
단위 시간 처리 수 = 처리량
응답이 시작될 때까지 = 응답 시간
전체 결과 완료까지 = 경과 시간
```

## 5. 성능 테스트 유형

| 테스트          | 목적                                     |
| --------------- | ---------------------------------------- |
| 부하 테스트     | 예상 부하에서 성능 확인                  |
| 스트레스 테스트 | 한계를 넘는 부하에서 동작과 복구 확인    |
| 스파이크 테스트 | 부하가 갑자기 증가·감소할 때 확인        |
| 내구성 테스트   | 장시간 부하에서 누수와 성능 저하 확인    |
| 용량 테스트     | 데이터·사용자 규모 증가에 따른 한계 확인 |

```text
평상시 예상 부하 = Load
한계 초과 = Stress
갑작스러운 급증 = Spike
장시간 = Endurance
규모 한계 = Volume·Capacity
```

## 6. 신뢰성과 가용성

| 지표 | 의미                            |
| ---- | ------------------------------- |
| MTTF | 고장까지 평균 동작 시간         |
| MTTR | 고장 후 평균 수리·복구 시간     |
| MTBF | 고장과 다음 고장 사이 평균 시간 |

가용성의 대표 계산:

```text
가용성 = MTTF / (MTTF + MTTR)
```

MTTF가 길고 MTTR이 짧을수록 가용성이 높아진다.

## 7. 소프트웨어 유지보수

| 유형          | 의미                                             |
| ------------- | ------------------------------------------------ |
| 수정 유지보수 | 발견된 오류를 수정                               |
| 적응 유지보수 | 운영체제·법규·환경 변화에 대응                   |
| 완전 유지보수 | 성능·기능·사용성을 개선                          |
| 예방 유지보수 | 미래의 오류와 유지보수 비용을 줄이도록 구조 개선 |

```text
버그 수정 = 수정
환경 변화 대응 = 적응
기능·성능 개선 = 완전
미래 문제 예방 = 예방
```

## 8. 리팩터링과 재공학

### 리팩터링

외부 동작을 바꾸지 않고 내부 구조를 개선한다.

```text
중복 제거
복잡도 감소
이름과 구조 개선
테스트 가능성 향상
```

### 소프트웨어 재공학

기존 소프트웨어를 분석하고 재구성하여 품질과 유지보수성을 개선한다.

```text
분석 → 재구성 → 역공학·순공학 → 개선된 시스템
```

## 9. 역공학과 순공학

| 용어   | 의미                                       |
| ------ | ------------------------------------------ |
| 역공학 | 기존 코드에서 설계·요구 수준의 정보를 추출 |
| 순공학 | 요구·설계에서 구현 코드를 개발             |
| 재구성 | 외부 동작을 유지하며 내부 표현을 변경      |

## 10. 코드 품질 분석 도구

| 유형      | 의미                                        |
| --------- | ------------------------------------------- |
| 정적 분석 | 실행 없이 코드의 규칙 위반·결함·복잡도 분석 |
| 동적 분석 | 프로그램 실행 중 메모리·성능·오류 분석      |

## 11. 복잡도

순환 복잡도는 제어 흐름의 독립 경로 수를 나타낸다.

```text
V(G) = 간선 - 노드 + 2
V(G) = 조건 노드 + 1
```

복잡도가 높으면 테스트해야 할 경로와 유지보수 난도가 증가한다.

## 12. UI와 UX

| 구분 | 의미                                          |
| ---- | --------------------------------------------- |
| UI   | 사용자가 시스템과 상호작용하는 화면·조작 수단 |
| UX   | 서비스를 이용하며 느끼는 전체 경험과 만족     |

### UI 기본 원칙

```text
직관성: 누구나 쉽게 이해
유효성: 사용 목적을 정확히 달성
학습성: 쉽게 배우고 익힘
유연성: 다양한 요구를 수용하고 오류 최소화
```

## 13. 품질 비용

| 비용           | 의미                                        |
| -------------- | ------------------------------------------- |
| 예방 비용      | 결함을 만들지 않기 위한 교육·표준·개선 비용 |
| 평가 비용      | 테스트·검토로 결함을 찾는 비용              |
| 내부 실패 비용 | 출시 전 발견한 결함 수정 비용               |
| 외부 실패 비용 | 출시 후 장애·보상·신뢰 손실 비용            |

## 14. 시험 직전 암기

```text
단위 시간 처리 수 = 처리량
응답 시작까지 = 응답 시간
전체 완료까지 = 경과 시간
예상 부하 = 부하 테스트
한계 초과 = 스트레스 테스트
갑작스러운 증가 = 스파이크 테스트
장시간 = 내구성 테스트
버그 수정 = 수정 유지보수
환경 대응 = 적응 유지보수
성능 개선 = 완전 유지보수
미래 문제 방지 = 예방 유지보수
외부 동작 유지·내부 개선 = 리팩터링
코드에서 설계 추출 = 역공학
화면·조작 = UI
전체 경험 = UX
```
