[Echo 인프라 시리즈 전체 목차](/blog/2026-11-05-echo-infra-series)

> 2026년 11월 4일 기준 해커톤 구현 회고입니다. 당시 코드와 작업 기록을 기준으로 정리했으며, 현재 서비스 상태나 모든 환경에 적용되는 설정을 보장하지 않습니다.

## 기술 명칭과 설명

Terraform은 원하는 클라우드 자원을 코드로 선언하고 실제 환경과의 차이를 계산하는 도구입니다. IaC(Infrastructure as Code)는 인프라를 코드로 관리하는 방식이고, State는 코드 속 자원과 실제 자원의 대응 관계를 기록한 상태입니다. 원격 State는 이 상태를 팀이 공유하는 저장소에 둡니다.

## 내가 무엇을 했는가

bootstrap/aws·gcp에 상태 버킷을 정의했습니다. AWS·GCP의 dev 루트를 분리하고 버전·provider lock·이름·태그 규칙을 고정했습니다. make up/down/plan, fmt→validate→tflint 검사와 출력값 계약을 추가했습니다. 상태 버킷에는 prevent_destroy를 추가했습니다.

## 트러블슈팅: 문제 → 원인/판단 → 조치

검사 스크립트가 backend State와 클라우드 인증에 의존하는 문제가 있었습니다. 31032d2에서 검사 초기화를 backend 없이 수행하도록 바꾸었습니다. 이후 7b5e4c4에서 루트별 고정 검사 데이터 디렉터리로 재실행 비용을 줄였습니다. 이는 정적 검증 경로 개선이지 실제 apply 성공을 보장하는 검사는 아닙니다.

## 해결 결과와 아직 남은 한계

인프라 코드와 팀 전달 계약은 존재합니다. 전체 환경을 빈 상태에서 다시 만드는 리허설은 설계 문서에서 TBD입니다. prevent_destroy는 Terraform 삭제 방지 장치이지 콘솔 삭제까지 차단하는 보안 정책은 아닙니다.

## 발표·면접에서 설명할 문장

> 클라우드 환경을 코드로 관리하면서, 검사 단계와 실제 자격 증명이 필요한 적용 단계를 분리했습니다.

## 기여 범위와 검증 기준

본인 작성의 비병합 커밋과 변경 내용을 대조했습니다. 코드 구현, 적용 기록, 실측 결과는 구분합니다. 팀원이 만든 기반을 확장한 작업은 그 경계를 본문에 명시했고, 목표 수치는 완료 성과로 표현하지 않았습니다. 운영 경로와 식별자는 공개본에서 생략했습니다.
