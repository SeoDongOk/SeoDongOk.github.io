> 2026년 11월 4일 기준 해커톤 구현 회고입니다. 당시 코드와 작업 기록을 기준으로 정리했으며, 현재 서비스 상태나 모든 환경에 적용되는 설정을 보장하지 않습니다.

## 기술 명칭과 설명

Envoy는 HTTP 같은 애플리케이션 계층 요청을 전달하는 프록시입니다. 가중치 라우팅은 여러 목적지로 요청을 비율에 따라 나누는 방식입니다. xDS는 Envoy 설정을 동적으로 전달하는 체계이며 여기서는 파일 기반으로 사용합니다. 헬스체크는 목적지 생존 여부를 주기적으로 확인합니다.

## 내가 무엇을 했는가

Envoy·weights-api·관측 스택을 구성하고 서울의 고정 진입점 VM으로 배치했습니다. weights-api가 동적 라우팅 파일을 갱신해 재시작 없이 AWS/GCP 비율을 바꾸도록 했습니다. aggregate 클러스터로 우선 목적지가 죽으면 다른 환경으로 흐르게 했고 출력값·측정 계약을 정리했습니다.

## 트러블슈팅: 문제 → 원인/판단 → 조치

DNS 가중치는 TTL·캐시 때문에 요청 단위 비율과 반영 시점을 제어하기 어려웠습니다. 건수 기반 승격과 빠른 복귀 요구에 맞춰 프록시 가중치를 선택했습니다. 이는 오류 수정이라기보다 설계 선택입니다. 트래픽을 한 VM에 모으는 단일 장애점과 추가 네트워크 홉이라는 대가도 남습니다.

## 해결 결과와 아직 남은 한계

로컬 반영·우회 측정이 문서에 있지만 2초 간격·2회 실패 설정을 모든 장애에서 1초 이내 보장으로 표현하지 않습니다. 운영 단계 승격 판정과 API 실행 루프는 echo-was 담당 영역입니다.

## 발표·면접에서 설명할 문장

> DNS는 대표 주소 역할에 두고 실제 클라우드 간 비율은 Envoy에서 제어해, 요청 건수로 전환 결과를 확인할 수 있게 했습니다.

## 기여 범위와 검증 기준

본인 작성의 비병합 커밋과 변경 내용을 대조했습니다. 코드 구현, 적용 기록, 실측 결과는 구분합니다. 팀원이 만든 기반을 확장한 작업은 그 경계를 본문에 명시했고, 목표 수치는 완료 성과로 표현하지 않았습니다. 운영 경로와 식별자는 공개본에서 생략했습니다.
