정보처리기사 실기 데이터베이스 영역은 용어의 정의가 명확하고 반복되는 문제 유형이 많다. SQL 작성 능력과 별개로 **비슷한 DB 용어를 정확히 구분하는 것**이 핵심이다.

## 1. 가장 먼저 외울 릴레이션 용어

| 용어                    | 의미                                 | 시험 식별어      |
| ----------------------- | ------------------------------------ | ---------------- |
| 릴레이션(Relation)      | 행과 열로 구성된 논리적 테이블       | 테이블           |
| 튜플(Tuple)             | 릴레이션을 구성하는 한 행            | 행, 레코드       |
| 속성(Attribute)         | 개체의 특성을 나타내는 한 열         | 열, 필드         |
| 카디널리티(Cardinality) | 릴레이션의 튜플 수                   | 행의 수, 기수    |
| 차수(Degree)            | 릴레이션의 속성 수                   | 열의 수          |
| 도메인(Domain)          | 한 속성이 가질 수 있는 원자값의 집합 | 값의 범위        |
| 릴레이션 스키마         | 릴레이션의 논리적 구조               | 구조, 정의       |
| 릴레이션 인스턴스       | 특정 시점에 저장된 실제 튜플의 집합  | 현재 데이터 상태 |

```text
행 = 튜플 = 레코드
열 = 속성 = 필드
행의 수 = 카디널리티
열의 수 = 차수
```

예를 들어 5행 3열 테이블이면 카디널리티는 5, 차수는 3이다.

## 2. 스키마 3계층

| 계층        | 관점                      | 핵심                             |
| ----------- | ------------------------- | -------------------------------- |
| 외부 스키마 | 개별 사용자·응용 프로그램 | 사용자별 뷰                      |
| 개념 스키마 | 조직 전체                 | 전체 DB의 논리 구조, 하나만 존재 |
| 내부 스키마 | 저장 장치                 | 물리적 저장 구조와 접근 경로     |

### 데이터 독립성

| 독립성               | 의미                                                  |
| -------------------- | ----------------------------------------------------- |
| 논리적 데이터 독립성 | 개념 스키마 변경이 외부 스키마에 미치는 영향을 최소화 |
| 물리적 데이터 독립성 | 내부 스키마 변경이 개념 스키마에 미치는 영향을 최소화 |

```text
물리적 저장 방식 변경 → 물리적 데이터 독립성
전체 논리 구조 변경 → 논리적 데이터 독립성
```

## 3. 키의 종류

| 키     | 조건·의미                         |
| ------ | --------------------------------- |
| 슈퍼키 | 튜플을 유일하게 식별, 유일성 만족 |
| 후보키 | 유일성 + 최소성 만족              |
| 기본키 | 후보키 중 대표로 선택             |
| 대체키 | 기본키로 선택되지 않은 후보키     |
| 외래키 | 다른 릴레이션의 기본키를 참조     |
| 복합키 | 둘 이상의 속성으로 구성된 키      |

### 예제

```text
학생(학번, 주민번호, 이름, 학과코드)

후보키: 학번, 주민번호
기본키: 학번
대체키: 주민번호
슈퍼키: 학번, 주민번호, (학번, 이름) 등
외래키: 학과코드
```

`(학번, 이름)`은 유일하지만 이름이 없어도 학번만으로 식별할 수 있으므로 최소성을 만족하지 않는다. 따라서 후보키가 아니라 슈퍼키다.

```text
슈퍼키 = 유일성
후보키 = 유일성 + 최소성
```

## 4. 무결성

| 무결성             | 핵심 규칙                                     |
| ------------------ | --------------------------------------------- |
| 개체 무결성        | 기본키는 NULL과 중복값을 가질 수 없음         |
| 참조 무결성        | 외래키는 참조 릴레이션의 기본키 값이거나 NULL |
| 도메인 무결성      | 속성값은 정의된 도메인에 속해야 함            |
| 사용자 정의 무결성 | 업무 규칙이 정의한 조건을 만족해야 함         |

```text
기본키 문제 → 개체 무결성
외래키 문제 → 참조 무결성
값의 범위 문제 → 도메인 무결성
```

## 5. 데이터베이스 설계 순서

```text
요구사항 분석
→ 개념적 설계
→ 논리적 설계
→ 물리적 설계
→ 구현
```

| 단계          | 주요 작업                                          |
| ------------- | -------------------------------------------------- |
| 요구사항 분석 | 사용자 요구 수집, 데이터와 처리 요구 분석          |
| 개념적 설계   | DBMS와 독립적인 개념 구조, E-R 모델 작성           |
| 논리적 설계   | 목표 DBMS에 맞는 논리 스키마와 테이블 설계         |
| 물리적 설계   | 저장 구조, 인덱스, 접근 경로, 레코드 배치 결정     |
| 구현          | DDL로 스키마 생성, 데이터 적재, 응용 프로그램 연동 |

```text
E-R 다이어그램 → 개념적 설계
테이블·스키마 변환 → 논리적 설계
인덱스·저장 구조 → 물리적 설계
```

## 6. E-R 모델

| 요소               | 의미                                      |
| ------------------ | ----------------------------------------- |
| 개체(Entity)       | 현실 세계에서 독립적으로 식별 가능한 대상 |
| 속성(Attribute)    | 개체가 가진 특성                          |
| 관계(Relationship) | 개체 사이의 연관성                        |

### 관계 대응수

```text
1:1  — 한 개체가 상대 개체 하나와 관계
1:N  — 한 개체가 상대 개체 여러 개와 관계
N:M  — 양쪽 모두 여러 개와 관계
```

N:M 관계는 관계형 데이터베이스에서 일반적으로 **교차·연결 테이블**로 분해한다.

## 7. 함수 종속

`X → Y`는 X의 값이 정해지면 Y의 값이 하나로 정해진다는 뜻이다. X는 결정자, Y는 종속자다.

| 종속           | 의미                                   |
| -------------- | -------------------------------------- |
| 완전 함수 종속 | 기본키 전체에 종속                     |
| 부분 함수 종속 | 복합키의 일부에 종속                   |
| 이행 함수 종속 | X→Y, Y→Z를 통해 X→Z가 성립             |
| 다치 종속      | 하나의 X에 여러 Y 값이 독립적으로 대응 |

## 8. 이상 현상

| 이상      | 문제 상황                                        |
| --------- | ------------------------------------------------ |
| 삽입 이상 | 불필요한 데이터까지 입력해야 새 정보를 삽입 가능 |
| 갱신 이상 | 중복 데이터 일부만 수정되어 값이 불일치          |
| 삭제 이상 | 한 정보를 삭제하면서 필요한 정보까지 함께 삭제   |

정규화는 중복을 줄여 이러한 이상 현상을 방지한다.

## 9. 정규화

| 정규형 | 제거 대상                                     |
| ------ | --------------------------------------------- |
| 1NF    | 반복 속성 제거, 모든 속성값을 원자값으로 구성 |
| 2NF    | 부분 함수 종속 제거                           |
| 3NF    | 이행 함수 종속 제거                           |
| BCNF   | 모든 결정자가 후보키가 되도록 분해            |
| 4NF    | 다치 종속 제거                                |
| 5NF    | 조인 종속 제거                                |

### 2NF 예제

```text
수강(학번, 과목코드, 학생이름, 과목명, 성적)
기본키: (학번, 과목코드)

(학번, 과목코드) → 성적
학번 → 학생이름
과목코드 → 과목명
```

학생이름과 과목명이 복합키 일부에 종속되므로 부분 함수 종속이다. 학생, 과목, 수강 릴레이션으로 분리하면 2NF를 만족한다.

### 3NF 예제

```text
학생(학번, 학과코드, 학과명)

학번 → 학과코드
학과코드 → 학과명
```

학번에서 학과명을 결정하는 과정에 학과코드가 있으므로 이행 함수 종속이다. 학생과 학과 릴레이션으로 분리하면 3NF를 만족한다.

```text
1NF = 원자값
2NF = 부분 종속 제거
3NF = 이행 종속 제거
BCNF = 모든 결정자가 후보키
```

## 10. 반정규화

정규화된 구조의 조회 성능을 높이기 위해 의도적으로 데이터 중복, 테이블 통합, 계산값 저장 등을 적용하는 작업이다.

| 장점             | 단점                              |
| ---------------- | --------------------------------- |
| 조인 감소        | 데이터 중복 증가                  |
| 조회 성능 향상   | 저장 공간 증가                    |
| 조회 쿼리 단순화 | 변경 비용과 무결성 관리 부담 증가 |

```text
정규화 = 일관성과 무결성
반정규화 = 조회 성능
```

## 11. 트랜잭션 ACID

| 특성                | 의미                                      |
| ------------------- | ----------------------------------------- |
| 원자성(Atomicity)   | 연산을 전부 수행하거나 전부 취소          |
| 일관성(Consistency) | 트랜잭션 전후 무결성 유지                 |
| 격리성(Isolation)   | 동시 트랜잭션이 서로 간섭하지 않도록 실행 |
| 영속성(Durability)  | 커밋된 결과를 영구적으로 보존             |

```text
원일격영
원자성-일관성-격리성-영속성
```

### 트랜잭션 제어

| 명령      | 의미                            |
| --------- | ------------------------------- |
| COMMIT    | 변경사항을 영구 반영            |
| ROLLBACK  | 변경사항 취소                   |
| SAVEPOINT | 트랜잭션 내 중간 복구 지점 설정 |

## 12. 병행 제어 문제

| 현상                   | 의미                                           |
| ---------------------- | ---------------------------------------------- |
| 갱신 분실(Lost Update) | 한 트랜잭션의 갱신이 다른 갱신에 덮임          |
| Dirty Read             | 커밋되지 않은 데이터를 읽음                    |
| Non-repeatable Read    | 같은 행을 다시 읽었는데 값이 달라짐            |
| Phantom Read           | 같은 조건으로 다시 조회했는데 행 집합이 달라짐 |

```text
Non-repeatable Read = 기존 행의 값 변경
Phantom Read = 조건에 해당하는 행의 추가·삭제
```

### 로킹

- 공유 잠금: 읽기 가능, 다른 공유 잠금 허용
- 배타 잠금: 읽기·쓰기 독점, 다른 잠금 제한
- 로킹 단위가 크면 관리 비용은 감소하지만 병행성도 감소한다.
- 로킹 단위가 작으면 병행성은 증가하지만 잠금 관리 비용도 증가한다.

## 13. 관계대수

관계대수는 원하는 결과를 얻기 위해 **어떻게 처리할지** 연산 순서를 명시하는 절차적 언어다.

| 연산              | 기호 | 의미                                           |
| ----------------- | ---- | ---------------------------------------------- |
| 셀렉트(Select)    | σ    | 조건을 만족하는 튜플 추출, 수평 연산           |
| 프로젝트(Project) | π    | 지정한 속성 추출, 수직 연산                    |
| 조인(Join)        | ⋈    | 공통 속성을 중심으로 릴레이션 결합             |
| 디비전(Division)  | ÷    | 상대 릴레이션의 모든 조건을 만족하는 튜플 추출 |
| 합집합            | ∪    | 두 릴레이션의 튜플 합집합                      |
| 교집합            | ∩    | 공통 튜플 추출                                 |
| 차집합            | −    | 첫 릴레이션에만 있는 튜플 추출                 |
| 카티션 프로덕트   | ×    | 두 릴레이션의 가능한 모든 튜플 조합            |

합집합, 교집합, 차집합을 수행하려면 두 릴레이션이 합병 가능해야 한다.

## 14. 뷰와 인덱스

### 뷰(View)

- 하나 이상의 기본 테이블에서 유도된 가상 테이블
- 데이터의 논리적 독립성과 보안 제공
- 복잡한 질의를 단순화
- 일반적인 뷰는 독립적인 실제 데이터를 저장하지 않음

### 인덱스(Index)

- 검색 속도를 향상하는 보조 자료구조
- 추가 저장 공간 필요
- INSERT, UPDATE, DELETE 시 인덱스 관리 비용 발생
- 선택도가 높은 검색 열에 효과적

## 15. 시험 직전 5점 점검

```text
후보키 = 유일성 + 최소성
카디널리티 = 행, 차수 = 열
개체 무결성 = 기본키
참조 무결성 = 외래키
도메인 = 속성값의 범위
외부-개념-내부 스키마
개념적 설계 = E-R 모델
논리적 설계 = 테이블·스키마
물리적 설계 = 저장·인덱스
2NF = 부분 종속 제거
3NF = 이행 종속 제거
ACID = 원자성·일관성·격리성·영속성
셀렉트 = 행, 프로젝트 = 열
```

DB 이론 문제는 문제 설명의 핵심 명사를 표시하면 정답 범위가 빠르게 좁혀진다. `기본키`, `외래키`, `행`, `열`, `복합키 일부`, `중간 결정자` 같은 식별어를 먼저 찾는다.
