> 2026년 11월 4일 기준 해커톤 구현 회고입니다. 당시 코드와 작업 기록을 기준으로 정리했으며, 현재 서비스 상태나 모든 환경에 적용되는 설정을 보장하지 않습니다.

## 기술 명칭과 설명

VPC는 AWS 안의 격리된 네트워크입니다. Subnet은 그 안의 주소 구역이고 NAT Gateway는 비공개 노드가 외부로 통신할 출구입니다. EKS는 AWS 관리형 Kubernetes이며, 관리형 노드 그룹은 앱이 실행될 EC2 묶음입니다. EBS CSI는 Kubernetes에서 AWS 디스크를 연결하도록 돕는 드라이버입니다.

## 내가 무엇을 했는가

AWS 도쿄 dev 루트에 VPC·서브넷·NAT, EKS·관리형 노드 그룹·Access Entry를 정의했습니다. EKS 감사 로그와 노드 IMDSv2 제한을 추가했고 EBS CSI·gp3 기본 StorageClass를 준비했습니다. 팀이 쓸 클러스터 이름과 네트워크 출력값도 계약으로 정리했습니다.

## 트러블슈팅: 문제 → 원인/판단 → 조치

EKS 노드 그룹이 CREATING에 머무는 문제가 있었습니다. ae153f9의 기록에 따르면 당시 무료 플랜 계정에서 t3.large의 RunInstances가 거부됐습니다. 해당 계정에서 허용되는 m7i-flex.large로 바꾸었습니다. 이 경험을 모든 AWS 계정의 인스턴스 제약으로 일반화하지 않습니다.

## 해결 결과와 아직 남은 한계

EKS 기반은 적용된 것으로 작업 문서에 기록되어 있습니다. EBS CSI 추가는 DB 저장소 기반 작업이며 데이터 담당의 PostgreSQL 전체 구현과 동일하지 않습니다. NAT·EKS는 과금 자원이며 예산 알림은 비용 상한 차단기가 아닙니다.

## 발표·면접에서 설명할 문장

> 비공개 노드 기반 EKS를 구성했고, 노드 생성 정체를 계정 플랜의 인스턴스 실행 제약으로 좁혀 해결했습니다.

## 기여 범위와 검증 기준

본인 작성의 비병합 커밋과 변경 내용을 대조했습니다. 코드 구현, 적용 기록, 실측 결과는 구분합니다. 팀원이 만든 기반을 확장한 작업은 그 경계를 본문에 명시했고, 목표 수치는 완료 성과로 표현하지 않았습니다. 운영 경로와 식별자는 공개본에서 생략했습니다.
