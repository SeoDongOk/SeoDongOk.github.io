## 질문

집에 기기가 열 대인데 공인 IP는 하나다. 서버의 응답은 어떻게 내 노트북을 정확히 찾아올까?

## 공인 IP와 사설 IP

- **공인 IP:** 인터넷 전체에서 유일한 주소. 돈을 내고 받는다.
- **사설 IP:** 내부에서만 쓰는 주소(`10.x`, `172.16~31.x`, `192.168.x`). 인터넷 라우터는 이 주소를 목적지로 하는 패킷을 받지 않는다.

IPv4 주소는 43억 개뿐이라 모든 기기에 공인 IP를 줄 수 없다. 그래서 안에서는 사설 IP를 쓰고, 밖으로 나갈 때만 공인 IP로 바꾼다. 이게 **NAT**(주소 변환)다.

## SNAT: 나갈 때 출발지를 바꾼다

```
노트북 192.168.0.10:51000  →  공유기  →  203.0.113.7:40001  →  서버
                         (출발지를 공인 IP:새 포트로 바꿈)
```

공유기는 바꾼 내용을 표에 적어 둔다.

| 안쪽 | 바깥쪽 | 상대 |
|---|---|---|
| 192.168.0.10:51000 | 203.0.113.7:40001 | 93.184.215.14:443 |

응답이 `203.0.113.7:40001` 로 돌아오면, 공유기는 이 표를 보고 목적지를 `192.168.0.10:51000` 으로 되돌려 넘긴다. 이 표를 **연결 추적**(리눅스에서는 conntrack)이라고 한다. 포트까지 바꿔서 여러 기기가 공인 IP 하나를 나눠 쓰는 방식을 정확히는 NAPT, 리눅스에서는 마스커레이드라고 부른다.

## DNAT: 들어올 때 목적지를 바꾼다

반대 방향이다. 밖에서 `공인 IP:443` 으로 온 요청을 안쪽 서버 `10.0.1.20:8080` 으로 넘긴다. 공유기의 포트 포워딩, 로드밸런서, 쿠버네티스 Service가 모두 DNAT의 일종이다.

| | SNAT | DNAT |
|---|---|---|
| 바꾸는 것 | 출발지 주소 | 목적지 주소 |
| 언제 | 안에서 밖으로 나갈 때 | 밖에서 안으로 들어올 때 |
| 예 | 공유기, NAT 게이트웨이 | 포트 포워딩, 로드밸런서, k8s Service |

## NAT의 함정

**1. 응답은 같은 NAT를 지나야 한다.** 연결 추적 표는 그 NAT에만 있다. 갈 때와 올 때 길이 다르면(비대칭 라우팅) 응답이 엉뚱한 NAT에 도착해 버려진다. 여러 네트워크 인터페이스나 여러 NAT가 있는 구성에서 "가끔만 안 되는" 장애로 나타난다.

**2. 포트는 유한하다.** 공인 IP 하나, 같은 목적지(IP·포트) 하나에 대해 쓸 수 있는 출발지 포트는 최대 약 6만 개다. 같은 외부 API에 짧은 연결을 미친 듯이 만들면 바닥난다(포트 고갈). TIME_WAIT까지 겹치면 더 빨리 바닥난다(03편).

**3. 상대 쪽에서는 NAT의 IP만 보인다.** 외부 서비스의 허용 목록에 우리 쪽 출발지 IP를 등록할 때는 **NAT의 공인 IP**를 넣어야 한다. 이 IP가 바뀌면(NAT를 다시 만들면) 허용 목록을 전부 고쳐야 한다. 그래서 고정 IP(Elastic IP, 예약 주소)를 붙이고, 가능하면 IP 대신 신원 기반 인증을 쓴다.

## 직접 확인 (맥 터미널)

```bash
# 내 사설 IP
ipconfig getifaddr en0

# 바깥에서 보이는 내 공인 IP (NAT를 거친 주소)
curl -s https://checkip.amazonaws.com

# 두 값이 다르면 NAT 뒤에 있다는 뜻
```

리눅스 서버가 있다면 `sudo conntrack -L | head` 로 연결 추적 표를, `sudo iptables -t nat -L -n -v` 로 NAT 규칙을 볼 수 있다.

## 클라우드에서는

| 구성 | 하는 일 |
|---|---|
| AWS NAT 게이트웨이, GCP Cloud NAT | 사설 서브넷의 SNAT. 밖으로 나가기만 가능 |
| 인터넷 게이트웨이 + 공인 IP | 인스턴스의 사설 IP와 공인 IP를 1:1로 변환 |
| 로드밸런서 | DNAT. 들어온 요청을 뒤의 서버로 |
| 쿠버네티스 Service (kube-proxy) | ClusterIP를 파드 IP로 DNAT |

- NAT 게이트웨이는 AZ마다 두는 게 정석이다. 하나만 두면 그 AZ가 죽을 때 모든 사설 서브넷이 밖으로 못 나간다.
- NAT 게이트웨이는 켜 둔 시간과 처리한 데이터 양으로 과금된다. S3 같은 같은 리전 서비스는 VPC 엔드포인트로 돌리면 NAT를 안 거쳐서 싸다.
- 쿠버네티스에서 파드가 외부로 나갈 때 노드 IP로 SNAT할지, 파드 IP 그대로 VPC 라우팅에 맡길지는 CNI 설정이 정한다. 여기서 비대칭 경로가 생기면 함정 1번 장애가 난다.

## 면접 한 줄 답

> NATはプライベートIPとグローバルIPを変換する仕組みです。送信元を変えるのがSNAT、宛先を変えるのがDNATで、変換の対応表を保持しているので、応答は同じNATを通る必要があります。

NAT는 사설 IP와 공인 IP를 변환하는 구조입니다. 출발지를 바꾸는 게 SNAT, 목적지를 바꾸는 게 DNAT이고, 변환 대응표를 갖고 있어서 응답은 같은 NAT를 지나야 합니다.
