정보처리기사 실기에서 SQL은 맞힐 수 있을 것 같으면서도 실수가 많이 난다.  
특히 `GROUP BY`, `HAVING`, `JOIN`, `NULL`, 서브쿼리가 섞이면 결과 행을 잘못 계산하기 쉽다.

이번 글은 SQL 고난이도 문제를 시험 풀이 순서 중심으로 정리한다.

## 1. SQL 실행 순서

가장 먼저 외워야 할 것은 SELECT문의 논리적 실행 순서다.

```text
FROM
→ WHERE
→ GROUP BY
→ HAVING
→ SELECT
→ ORDER BY
```

암기:

```text
프웨어그해셀오
FROM WHERE GROUP HAVING SELECT ORDER
```

문제를 풀 때는 절대 SELECT부터 보지 않는다.  
항상 FROM과 JOIN으로 대상 행을 만든 뒤 WHERE로 행을 걸러야 한다.

## 2. WHERE와 HAVING 차이

| 구분           | WHERE           | HAVING    |
| -------------- | --------------- | --------- |
| 처리 시점      | 그룹화 전       | 그룹화 후 |
| 대상           | 개별 행         | 그룹      |
| 집계 함수 사용 | 일반적으로 불가 | 가능      |

예시:

```sql
SELECT dept, COUNT(*)
FROM employee
WHERE salary >= 3000
GROUP BY dept
HAVING COUNT(*) >= 2;
```

풀이 순서:

```text
1. employee에서 시작
2. salary >= 3000인 행만 남김
3. dept별 그룹화
4. 그룹별 COUNT가 2 이상인 그룹만 남김
5. dept, COUNT 출력
```

## 3. INNER JOIN과 OUTER JOIN

JOIN은 결과 행 수를 정확히 추적해야 한다.

| JOIN             | 의미                                   |
| ---------------- | -------------------------------------- |
| INNER JOIN       | 양쪽 모두 매칭되는 행만                |
| LEFT OUTER JOIN  | 왼쪽 테이블은 모두, 오른쪽 없으면 NULL |
| RIGHT OUTER JOIN | 오른쪽 테이블은 모두, 왼쪽 없으면 NULL |
| FULL OUTER JOIN  | 양쪽 모두 보존                         |
| CROSS JOIN       | 가능한 모든 조합                       |

시험에서 가장 많이 헷갈리는 것은 LEFT JOIN이다.

```sql
SELECT A.id, B.name
FROM A LEFT JOIN B
ON A.id = B.id;
```

핵심:

```text
A는 전부 나온다.
B에 매칭이 없으면 B 컬럼은 NULL이다.
```

## 4. LEFT JOIN 후 WHERE 조건 주의

```sql
SELECT A.id, B.name
FROM A LEFT JOIN B
ON A.id = B.id
WHERE B.name = 'Kim';
```

이 경우 LEFT JOIN을 했더라도 `WHERE B.name = 'Kim'` 조건 때문에 B가 NULL인 행은 제거된다.  
결과적으로 INNER JOIN처럼 동작할 수 있다.

왼쪽 행을 보존하면서 오른쪽 조건을 걸고 싶다면 조건 위치를 조심해야 한다.

```sql
SELECT A.id, B.name
FROM A LEFT JOIN B
ON A.id = B.id AND B.name = 'Kim';
```

시험에서는 조건이 ON에 있는지 WHERE에 있는지 반드시 확인한다.

## 5. NULL 비교

NULL은 일반 비교 연산자로 비교하지 않는다.

| 잘못된 표현   | 올바른 표현       |
| ------------- | ----------------- |
| `col = NULL`  | `col IS NULL`     |
| `col != NULL` | `col IS NOT NULL` |

NULL 관련 함수도 정리한다.

| 함수              | 의미                          |
| ----------------- | ----------------------------- |
| COALESCE(a, b, c) | NULL이 아닌 첫 번째 값 반환   |
| NVL(a, b)         | a가 NULL이면 b 반환           |
| IFNULL(a, b)      | a가 NULL이면 b 반환           |
| NULLIF(a, b)      | a와 b가 같으면 NULL, 다르면 a |

DBMS마다 함수 이름이 다를 수 있지만, 시험에서는 개념이 중요하다.

## 6. COUNT와 NULL

집계 함수에서 NULL 처리가 중요하다.

| 표현         | 의미                    |
| ------------ | ----------------------- |
| `COUNT(*)`   | 전체 행 수              |
| `COUNT(col)` | col이 NULL이 아닌 행 수 |
| `SUM(col)`   | NULL 제외하고 합산      |
| `AVG(col)`   | NULL 제외하고 평균      |

예시:

| id  | score |
| --- | ----- |
| 1   | 80    |
| 2   | NULL  |
| 3   | 90    |

```sql
SELECT COUNT(*), COUNT(score), AVG(score)
FROM T;
```

결과:

```text
COUNT(*) = 3
COUNT(score) = 2
AVG(score) = 85
```

NULL은 평균 분모에도 포함되지 않는다.

## 7. GROUP BY 결과 계산법

예시 데이터:

| dept | name | salary |
| ---- | ---- | ------ |
| A    | Kim  | 3000   |
| A    | Lee  | 4000   |
| B    | Park | 2500   |
| B    | Choi | 3500   |
| C    | Jung | 2000   |

SQL:

```sql
SELECT dept, AVG(salary)
FROM employee
WHERE salary >= 3000
GROUP BY dept
HAVING COUNT(*) >= 2;
```

풀이:

```text
WHERE salary >= 3000 후 남는 행:
A Kim 3000
A Lee 4000
B Choi 3500

GROUP BY dept:
A: 2명, 평균 3500
B: 1명, 평균 3500

HAVING COUNT(*) >= 2:
A만 남음
```

결과:

```text
A 3500
```

## 8. 서브쿼리 패턴

서브쿼리는 한 줄씩 해석한다.

```sql
SELECT name
FROM employee
WHERE salary > (SELECT AVG(salary) FROM employee);
```

풀이:

```text
1. 서브쿼리에서 전체 평균 급여 계산
2. 바깥 쿼리에서 평균보다 큰 salary만 선택
3. 해당 name 출력
```

서브쿼리 유형:

| 유형             | 설명                                    |
| ---------------- | --------------------------------------- |
| 단일 행 서브쿼리 | 결과가 하나, `=`, `>`, `<` 사용         |
| 다중 행 서브쿼리 | 결과가 여러 행, `IN`, `ANY`, `ALL` 사용 |
| 상관 서브쿼리    | 바깥 쿼리 값을 안쪽에서 참조            |

## 9. IN, EXISTS 차이

| 구문   | 의미                               |
| ------ | ---------------------------------- |
| IN     | 값이 목록에 포함되는지 확인        |
| EXISTS | 서브쿼리 결과 행이 존재하는지 확인 |

```sql
SELECT name
FROM employee e
WHERE EXISTS (
    SELECT 1
    FROM department d
    WHERE d.dept_id = e.dept_id
);
```

EXISTS는 서브쿼리가 한 행이라도 반환하면 참이다.

## 10. DDL, DML, DCL, TCL

명령어 분류도 자주 나온다.

| 분류 | 명령어                         | 설명          |
| ---- | ------------------------------ | ------------- |
| DDL  | CREATE, ALTER, DROP, TRUNCATE  | 구조 정의     |
| DML  | SELECT, INSERT, UPDATE, DELETE | 데이터 조작   |
| DCL  | GRANT, REVOKE                  | 권한 제어     |
| TCL  | COMMIT, ROLLBACK, SAVEPOINT    | 트랜잭션 제어 |

주의할 점:

```text
DELETE는 DML
TRUNCATE는 DDL
DROP은 DDL
```

## 11. DELETE, TRUNCATE, DROP 비교

| 구분        | DELETE           | TRUNCATE          | DROP               |
| ----------- | ---------------- | ----------------- | ------------------ |
| 분류        | DML              | DDL               | DDL                |
| 대상        | 데이터 일부/전체 | 데이터 전체       | 테이블 구조+데이터 |
| WHERE       | 가능             | 불가              | 불가               |
| 롤백        | 가능할 수 있음   | 일반적으로 어려움 | 일반적으로 어려움  |
| 테이블 구조 | 유지             | 유지              | 삭제               |

시험에서는 이 비교가 자주 나온다.

## 12. 권한 관련 SQL

```sql
GRANT SELECT ON table_name TO user_name;
REVOKE SELECT ON table_name FROM user_name;
```

| 키워드            | 의미                                       |
| ----------------- | ------------------------------------------ |
| GRANT             | 권한 부여                                  |
| REVOKE            | 권한 회수                                  |
| WITH GRANT OPTION | 받은 권한을 다른 사용자에게 다시 부여 가능 |
| CASCADE           | 연쇄 회수                                  |

`WITH GRANT OPTION`과 `CASCADE`를 헷갈리지 않는다.

## 13. SQL 문제 풀이 체크리스트

```text
FROM/JOIN으로 원본 행을 만들었는가?
WHERE 조건을 먼저 적용했는가?
GROUP BY로 그룹을 나누었는가?
HAVING 조건은 그룹 기준으로 적용했는가?
COUNT(*)와 COUNT(col)의 차이를 확인했는가?
NULL 비교를 IS NULL로 처리했는가?
LEFT JOIN 뒤 WHERE 조건으로 NULL 행이 제거되지 않았는가?
ORDER BY는 마지막에 적용했는가?
```

## 14. 시험 직전 암기

```text
SQL 실행 순서: FROM → WHERE → GROUP BY → HAVING → SELECT → ORDER BY
WHERE: 그룹화 전 개별 행 조건
HAVING: 그룹화 후 그룹 조건
COUNT(*): 전체 행
COUNT(col): NULL 제외
NULL 비교: IS NULL, IS NOT NULL
LEFT JOIN: 왼쪽 전부 보존, 오른쪽 없으면 NULL
DELETE: DML, WHERE 가능
TRUNCATE: DDL, 전체 데이터 삭제, 구조 유지
DROP: DDL, 구조까지 삭제
GRANT: 권한 부여
REVOKE: 권한 회수
```

## 마무리

SQL 문제는 문법보다 **실행 순서 추적**이 핵심이다.  
특히 시험장에서 급하게 풀면 SELECT에 보이는 컬럼부터 해석하려고 하는데, 반드시 FROM부터 봐야 한다.

```text
FROM에서 대상 만들기
WHERE로 행 제거
GROUP BY로 묶기
HAVING으로 그룹 제거
SELECT로 출력
ORDER BY로 정렬
```

이 순서만 고정해도 GROUP BY, JOIN, NULL 문제에서 실수를 크게 줄일 수 있다.
