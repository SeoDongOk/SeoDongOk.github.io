## 시험 직전 빈출도

> **우선순위 A · ★★★★☆**
>
> LRU는 2024년 회차 출제 이력이 확인되고 페이지 부재 계산으로 다시 나오기 쉽다.

- **최소 암기:** 페이징/세그먼테이션, 내부/외부 단편화, FIFO·LRU·LFU·OPT
- **5점 후보:** FIFO=먼저 들어온 페이지 / LRU=가장 오래 미사용 / OPT=앞으로 가장 늦게 사용
- **판정 기준:** 별점은 Q-Net의 공식 출제 확률이 아니다. 2020년 1회~2026년 1회 복원 목록과 2026 시나공 핵심요약의 실기 출제 이력 표기를 개념군 단위로 교차해 정한 **시험 전날 상대 우선순위**다.

메모리 관리 문제는 내부·외부 단편화와 페이지 교체 알고리즘을 구분하는 것이 핵심이다. 페이지 부재 횟수는 프레임 상태를 단계별로 표에 기록한다.

## 1. 기억장치 계층

```text
레지스터 → 캐시 → 주기억장치 → 보조기억장치
```

위로 갈수록 속도가 빠르고 용량이 작으며 단위 가격이 높다.

## 2. 가상 메모리

보조기억장치의 일부를 주기억장치처럼 사용하여 실제 메모리보다 큰 프로그램을 실행할 수 있게 하는 기법이다.

```text
논리 주소: 프로세스가 사용하는 가상 주소
물리 주소: 실제 메모리의 주소
MMU: 논리 주소를 물리 주소로 변환
```

## 3. 페이징과 세그먼테이션

| 구분        | 페이징      | 세그먼테이션         |
| ----------- | ----------- | -------------------- |
| 분할 단위   | 고정 크기   | 가변 크기            |
| 논리 단위   | 페이지      | 의미 단위의 세그먼트 |
| 물리 단위   | 프레임      | 가변 영역            |
| 주요 단편화 | 내부 단편화 | 외부 단편화          |

```text
고정 크기 → 페이징 → 내부 단편화
가변 크기 → 세그먼테이션 → 외부 단편화
```

## 4. 단편화

| 단편화      | 의미                                              |
| ----------- | ------------------------------------------------- |
| 내부 단편화 | 할당된 공간 내부에 사용하지 않는 영역 발생        |
| 외부 단편화 | 총 여유 공간은 충분하지만 연속되지 않아 할당 불가 |

외부 단편화 해결에 압축·집약을 사용할 수 있지만 데이터 이동 비용이 발생한다.

## 5. 페이지 테이블과 TLB

| 용어          | 의미                                     |
| ------------- | ---------------------------------------- |
| 페이지 테이블 | 페이지 번호와 프레임 번호의 매핑 저장    |
| TLB           | 최근 주소 변환 정보를 저장하는 고속 캐시 |
| 유효 비트     | 페이지가 메모리에 존재하는지 표시        |
| 변경 비트     | 페이지가 수정됐는지 표시                 |
| 참조 비트     | 최근 페이지 접근 여부 표시               |

## 6. 요구 페이징

필요한 페이지를 실제로 참조할 때 주기억장치로 적재한다.

### 페이지 부재 처리

```text
1. 페이지가 메모리에 없는 것을 확인
2. 운영체제에 트랩 발생
3. 빈 프레임 또는 교체할 페이지 선택
4. 보조기억장치에서 페이지 적재
5. 페이지 테이블 갱신
6. 중단된 명령 재실행
```

## 7. 페이지 교체 알고리즘

| 알고리즘 | 제거 대상                                      |
| -------- | ---------------------------------------------- |
| FIFO     | 가장 먼저 들어온 페이지                        |
| LRU      | 가장 오래 사용하지 않은 페이지                 |
| LFU      | 사용 빈도가 가장 낮은 페이지                   |
| MFU      | 사용 빈도가 가장 높은 페이지                   |
| OPT      | 앞으로 가장 늦게 사용될 페이지                 |
| NUR      | 최근 사용하지 않은 페이지, 참조·변경 비트 이용 |
| Clock    | 원형 큐와 참조 비트로 LRU를 근사               |

## 8. 알고리즘 식별어

```text
가장 오래 적재됨 → FIFO
가장 오래 참조되지 않음 → LRU
참조 횟수가 가장 적음 → LFU
미래에 가장 늦게 사용 → OPT
참조 비트와 원형 포인터 → Clock
```

## 9. 페이지 부재 계산법

```text
1. 프레임 수를 칸으로 그림
2. 참조 문자열을 왼쪽부터 처리
3. 이미 존재하면 Hit 표시
4. 없으면 Fault 표시 후 알고리즘에 따라 교체
5. 매 단계 프레임 상태 기록
```

LRU에서는 적재 시간이 아니라 **마지막으로 사용한 시점**을 확인한다.

## 10. Belady의 모순

FIFO에서 프레임 수를 늘렸는데도 페이지 부재 횟수가 증가할 수 있는 현상이다.

```text
프레임 증가 → 부재 증가 가능 → Belady의 모순 → FIFO
```

## 11. 스래싱

프로세스가 실제 작업보다 페이지 교체에 대부분의 시간을 사용하는 현상이다.

### 원인과 대응

```text
원인: 과도한 다중 프로그래밍, 부족한 프레임
대응: 다중 프로그래밍 정도 감소, 워킹셋·페이지 부재 빈도 이용
```

## 12. 워킹셋과 PFF

| 기법   | 의미                                                   |
| ------ | ------------------------------------------------------ |
| 워킹셋 | 일정 시간 동안 자주 참조한 페이지 집합을 메모리에 유지 |
| PFF    | 페이지 부재 빈도의 상·하한을 이용해 프레임 수 조절     |

## 13. 시험 직전 암기

```text
페이지 = 논리적 고정 단위
프레임 = 물리적 고정 단위
페이징 = 내부 단편화
세그먼테이션 = 외부 단편화
FIFO = 먼저 들어온 페이지
LRU = 오래 사용하지 않은 페이지
LFU = 사용 빈도 낮은 페이지
OPT = 미래에 가장 늦게 사용
Belady = FIFO
페이지 교체 과다 = 스래싱
```
