> 2026년 11월 4일 기준 해커톤 구현 회고입니다. 당시 코드와 작업 기록을 기준으로 정리했으며, 현재 서비스 상태나 모든 환경에 적용되는 설정을 보장하지 않습니다.

## 기술 명칭과 설명

Ingress는 HTTP 호스트·경로를 Kubernetes Service에 연결하는 규칙입니다. ALB는 AWS L7 로드밸런서이고 ingress-nginx는 NGINX 기반 Ingress Controller입니다. ACM은 AWS 인증서 관리 서비스입니다. TLS는 통신 암호화와 인증서 기반 서버 신원 검증을 지원합니다.

## 내가 무엇을 했는가

앱마다 LB를 만들지 않도록 환경별 공유 진입 경로를 준비했습니다. AWS는 ALB 그룹을 유지하는 닻 Ingress, GCP는 내부 LB 기반 ingress-nginx 경로입니다. AWS 닻에 HTTPS 443·ACM 인증서와 /healthz 고정 응답을 추가하고 Envoy 업스트림을 공유 경로로 바꾼 결과를 기록했습니다.

## 트러블슈팅: 문제 → 원인/판단 → 조치

Envoy 헬스체크의 Host=aws가 앱 호스트 규칙과 일치하지 않아 기본 404로 갈 수 있었습니다. c19b196에서 닻 Ingress에 정확한 /healthz 경로의 200 고정 응답을 추가했습니다. 다만 이 응답은 공유 앞문의 생존이지 개별 앱의 준비 완료를 증명하지 않습니다.

## 해결 결과와 아직 남은 한계

공유 경로 적용 기록이 있습니다. cert-manager·Cloudflare 수동 자원 이관 9240781은 API 담당 작성입니다. 인증서 발급 기관이나 Cloudflare 전체 설정을 본인이 모두 구축했다고 확장하지 않습니다.

## 발표·면접에서 설명할 문장

> 공유 Ingress로 앱별 LB 생성을 줄이고, 프록시의 헬스체크 Host가 실제 라우팅 규칙과 다른 문제를 별도 상태 경로로 해결했습니다.

## 기여 범위와 검증 기준

본인 작성의 비병합 커밋과 변경 내용을 대조했습니다. 코드 구현, 적용 기록, 실측 결과는 구분합니다. 팀원이 만든 기반을 확장한 작업은 그 경계를 본문에 명시했고, 목표 수치는 완료 성과로 표현하지 않았습니다. 운영 경로와 식별자는 공개본에서 생략했습니다.
