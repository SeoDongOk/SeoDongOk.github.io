## 시험 직전 빈출도

> **우선순위 A · ★★★★☆**
>
> 셀렉트·프로젝트·조인·디비전과 DB 설계 단계가 여러 회차에서 명칭·기호 문제로 출제됐다.

- **최소 암기:** σ 셀렉트, π 프로젝트, ⋈ 조인, ÷ 디비전, 요구→개념→논리→물리→구현
- **5점 후보:** 행 선택=셀렉트(σ), 열 선택=프로젝트(π), 모두 만족하는 몫=디비전(÷)
- **판정 기준:** 별점은 Q-Net의 공식 출제 확률이 아니다. 2020년 1회~2026년 1회 복원 목록과 2026 시나공 핵심요약의 실기 출제 이력 표기를 개념군 단위로 교차해 정한 **시험 전날 상대 우선순위**다.

관계대수는 연산 기호와 행·열 방향을 구분하는 문제가 많다. DB 설계에서는 **개념적 설계의 ERD**, **논리적 설계의 스키마**, **물리적 설계의 저장 구조**를 연결한다.

## 1. 관계대수와 관계해석

| 구분      | 관계대수           | 관계해석           |
| --------- | ------------------ | ------------------ |
| 성격      | 절차적             | 비절차적·선언적    |
| 핵심 질문 | 어떻게 구할 것인가 | 무엇을 구할 것인가 |
| 표현      | 연산자와 연산 순서 | 논리식과 조건      |

## 2. 순수 관계 연산

| 연산     | 기호 | 의미                                         |
| -------- | ---- | -------------------------------------------- |
| 셀렉트   | σ    | 조건에 맞는 튜플 추출                        |
| 프로젝트 | π    | 지정한 속성 추출                             |
| 조인     | ⋈    | 공통 속성을 기준으로 릴레이션 결합           |
| 디비전   | ÷    | 상대 릴레이션의 모든 조건을 만족하는 값 추출 |

```text
셀렉트 = 행 = 수평 연산
프로젝트 = 열 = 수직 연산
```

## 3. 일반 집합 연산

| 연산            | 기호 | 의미                          |
| --------------- | ---- | ----------------------------- |
| 합집합          | ∪    | 두 릴레이션의 모든 튜플       |
| 교집합          | ∩    | 두 릴레이션의 공통 튜플       |
| 차집합          | −    | 첫 릴레이션에만 존재하는 튜플 |
| 카티션 프로덕트 | ×    | 가능한 모든 튜플 순서쌍       |

합집합·교집합·차집합은 두 릴레이션이 합병 가능해야 한다.

```text
속성 수가 같음
대응 속성의 도메인이 같거나 호환됨
```

## 4. 조인 종류

| 조인      | 의미                                   |
| --------- | -------------------------------------- |
| 세타 조인 | 비교 연산 조건을 만족하는 튜플 결합    |
| 동등 조인 | `=` 조건으로 결합, 중복 속성 유지 가능 |
| 자연 조인 | 동등 조인 결과에서 중복 속성 제거      |
| 외부 조인 | 일치하지 않는 튜플도 NULL을 붙여 보존  |

## 5. 디비전 이해

```text
수강(학생, 과목)
필수과목(과목)
```

`수강 ÷ 필수과목`은 필수과목의 **모든 과목을 수강한 학생**을 구한다.

문제 설명에 `모두`, `전부`, `모든 조건`이 나타나면 디비전을 의심한다.

## 6. 데이터베이스 설계 절차

```text
요구사항 분석
→ 개념적 설계
→ 논리적 설계
→ 물리적 설계
→ 구현
```

## 7. 요구사항 분석

```text
사용자 요구 수집
데이터 요구 분석
처리 요구 분석
업무 규칙과 제약 확인
```

## 8. 개념적 설계

특정 DBMS와 독립적으로 현실 세계를 개념 구조로 표현한다.

```text
개체 식별
속성 정의
관계 정의
E-R 다이어그램 작성
```

| ER 요소 | 의미                        |
| ------- | --------------------------- |
| 개체    | 독립적으로 식별 가능한 대상 |
| 속성    | 개체가 가진 특성            |
| 관계    | 개체 사이의 연관성          |

## 9. 논리적 설계

개념 구조를 목표 데이터 모델에 맞는 논리 스키마로 변환한다.

```text
ER 모델을 릴레이션으로 변환
기본키와 외래키 결정
정규화 수행
무결성 제약 정의
```

## 10. 물리적 설계

저장 장치와 성능을 고려하여 실제 저장 구조와 접근 방법을 결정한다.

```text
파일 조직
레코드 배치
인덱스 선택
파티셔닝
접근 경로
저장 공간 산정
```

## 11. 스키마 3계층

| 계층        | 관점                           |
| ----------- | ------------------------------ |
| 외부 스키마 | 개별 사용자·응용 프로그램의 뷰 |
| 개념 스키마 | 조직 전체 DB의 논리적 구조     |
| 내부 스키마 | 물리적 저장 구조               |

## 12. 데이터 독립성

| 독립성        | 의미                                                |
| ------------- | --------------------------------------------------- |
| 논리적 독립성 | 개념 스키마 변경이 외부 스키마에 미치는 영향 최소화 |
| 물리적 독립성 | 내부 스키마 변경이 개념 스키마에 미치는 영향 최소화 |

## 13. 뷰와 인덱스

### 뷰

- 기본 테이블에서 유도된 가상 테이블
- 보안과 논리적 독립성 제공
- 복잡한 질의를 단순화

### 인덱스

- 검색 속도 향상
- 추가 저장 공간 필요
- 삽입·수정·삭제 시 관리 비용 발생
- 선택도가 높은 열의 조회에 유리

## 14. 시험 직전 암기

```text
관계대수 = 절차적 = 어떻게
관계해석 = 비절차적 = 무엇을
셀렉트 σ = 행
프로젝트 π = 열
조인 ⋈ = 결합
디비전 ÷ = 모든 조건 만족
개념적 설계 = ERD
논리적 설계 = 스키마·테이블·정규화
물리적 설계 = 저장·인덱스·접근 경로
외부 = 사용자
개념 = 전체 논리
내부 = 물리 저장
```
