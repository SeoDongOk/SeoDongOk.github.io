## 시험 직전 빈출도

> **우선순위 S · ★★★★★**
>
> 드라이버·스텁은 2020년 후반 회차부터 대표적인 반복 단답형이며 실제 오답 위험도 높다.

- **최소 암기:** 하향식=스텁, 상향식=드라이버, 빅뱅·샌드위치, 참/샘플링/휴리스틱/일관성 오라클
- **5점 후보:** 위에서 아래로 호출당하는 하위 모듈 대역=스텁 / 아래에서 위로 호출해 주는 상위 대역=드라이버
- **판정 기준:** 별점은 Q-Net의 공식 출제 확률이 아니다. 2020년 1회~2026년 1회 복원 목록과 2026 시나공 핵심요약의 실기 출제 이력 표기를 개념군 단위로 교차해 정한 **시험 전날 상대 우선순위**다.

통합 테스트에서 가장 중요한 한 문장은 **하향식은 스텁, 상향식은 드라이버**다. 설명에서 대체하는 모듈의 방향을 확인하면 바로 답할 수 있다.

## 1. 통합 테스트 목적

단위 테스트를 마친 모듈을 결합하면서 다음 문제를 확인한다.

```text
모듈 사이 인터페이스 오류
데이터 전달 오류
호출 순서 오류
예외 처리 불일치
공유 자원 충돌
```

## 2. 하향식 통합 테스트

최상위 모듈부터 아래 방향으로 통합한다.

```text
상위 모듈 먼저
→ 아직 없는 하위 모듈은 스텁으로 대체
→ 깊이 우선 또는 너비 우선 통합
```

### 특징

- 시스템의 주요 제어 흐름을 조기에 확인할 수 있다.
- 상위 설계와 인터페이스 오류를 일찍 발견한다.
- 하위 모듈이 없으면 스텁이 필요하다.
- 하위의 세부 기능은 늦게 검증될 수 있다.

## 3. 상향식 통합 테스트

최하위 모듈부터 위 방향으로 통합한다.

```text
하위 모듈 먼저
→ 관련 하위 모듈을 클러스터로 구성
→ 아직 없는 상위 모듈은 드라이버로 대체
```

### 특징

- 하위의 공통·핵심 모듈을 조기에 검증할 수 있다.
- 스텁은 필요하지 않지만 드라이버가 필요하다.
- 전체 시스템의 제어 흐름은 늦게 확인될 수 있다.

## 4. 스텁과 드라이버

| 구분      | 스텁(Stub)              | 드라이버(Driver)               |
| --------- | ----------------------- | ------------------------------ |
| 사용 전략 | 하향식                  | 상향식                         |
| 대체 대상 | 하위 모듈               | 상위 모듈                      |
| 동작      | 호출되면 단순 결과 반환 | 하위 모듈을 호출하고 결과 확인 |

암기:

```text
하스상드
하향식은 스텁, 상향식은 드라이버
```

### 문제 식별어

```text
하위 모듈 대신 임시 결과 반환 → 스텁
상위 모듈 대신 입력 전달·호출 → 드라이버
```

## 5. 기타 통합 전략

| 전략     | 의미                                | 특징                               |
| -------- | ----------------------------------- | ---------------------------------- |
| 빅뱅     | 모든 모듈을 한 번에 통합            | 간단하지만 오류 위치 추적이 어려움 |
| 샌드위치 | 하향식과 상향식을 동시에 수행       | 병렬 진행 가능, 관리 복잡          |
| 백본     | 핵심 골격을 먼저 구성하고 모듈 추가 | 주요 구조를 조기에 안정화          |

## 6. 회귀 테스트

변경이나 수정으로 기존 기능에 새로운 결함이 생기지 않았는지 확인한다.

```text
버그 수정 후 기존 기능 재검사
기능 추가 후 영향 범위 재검사
리팩터링 후 동작 보존 확인
```

자동화할 가치가 높은 테스트 유형이다.

## 7. 테스트 오라클

테스트 실행 결과가 올바른지 판단하기 위해 기대 결과를 제공하는 기준 또는 장치다.

| 유형               | 의미                                           |
| ------------------ | ---------------------------------------------- |
| 참 오라클          | 모든 입력에 대해 정확한 기대 결과 제공         |
| 샘플링 오라클      | 특정 입력에 대해서만 기대 결과 제공            |
| 추정 오라클        | 일부 입력의 정확한 결과를 기반으로 나머지 추정 |
| 일관성 검사 오라클 | 이전 실행 결과와 현재 실행 결과 비교           |

```text
모든 입력의 정확한 답 → 참 오라클
일부 입력만 정확한 답 → 샘플링 오라클
일부를 바탕으로 나머지 추정 → 추정 오라클
전후 실행 결과 비교 → 일관성 검사 오라클
```

## 8. 테스트 케이스 구성 요소

| 요소        | 의미                               |
| ----------- | ---------------------------------- |
| 식별자      | 테스트 케이스를 구분하는 번호·이름 |
| 테스트 항목 | 검증할 요구사항이나 기능           |
| 입력 명세   | 입력 데이터와 사전 조건            |
| 출력 명세   | 예상 결과                          |
| 환경 설정   | 하드웨어·소프트웨어·데이터 상태    |
| 특수 절차   | 실행에 필요한 별도 절차            |
| 의존성      | 선행 테스트나 관련 테스트          |

## 9. 테스트 시나리오와 테스트 케이스

```text
테스트 시나리오 = 무엇을 어떤 흐름으로 검증할지
테스트 케이스 = 입력·절차·예상 결과를 구체적으로 정의
테스트 스크립트 = 테스트 실행을 자동화한 명령·코드
```

## 10. 테스트 자동화 도구

| 유형             | 역할                                    |
| ---------------- | --------------------------------------- |
| 정적 분석 도구   | 실행 없이 코드 결함과 규칙 위반 분석    |
| 테스트 실행 도구 | 테스트 데이터를 이용해 대상 실행        |
| 성능 테스트 도구 | 처리량, 응답 시간, 자원 사용량 측정     |
| 테스트 통제 도구 | 테스트 계획·진행·결함·형상 관리         |
| 테스트 장치      | 스텁, 드라이버 등 테스트 지원 구성 요소 |

## 11. 시험 직전 암기

```text
하향식 = 상위부터 = 하위 대체 = 스텁
상향식 = 하위부터 = 상위 대체 = 드라이버
한 번에 모두 통합 = 빅뱅
하향식+상향식 = 샌드위치
수정 후 기존 기능 재검사 = 회귀 테스트
모든 입력의 기대 결과 = 참 오라클
일부 입력만 기대 결과 = 샘플링 오라클
실행 전후 결과 비교 = 일관성 검사 오라클
```
