정보처리기사 실기에서 다이어그램 문제는 “그림을 완벽하게 그리는 능력”보다 **다이어그램 이름과 구성요소를 구분하는 능력**이 중요하다.  
내가 약한 부분은 유스케이스, 클래스, 시퀀스, 활동, 상태, ERD, DFD가 한꺼번에 나오면 헷갈리는 점이다.

이번 글은 다이어그램을 시험 답안용으로 정리한다.

## 1. UML이란?

UML은 Unified Modeling Language의 약자다.  
소프트웨어 시스템을 시각적으로 표현하기 위한 표준 모델링 언어다.

시험 답안에서는 이렇게 정리할 수 있다.

```text
UML은 시스템의 구조와 행위를 시각적으로 모델링하기 위한 표준화된 모델링 언어이다.
```

UML은 크게 두 종류로 나눌 수 있다.

| 구분            | 설명                      | 대표 다이어그램                |
| --------------- | ------------------------- | ------------------------------ |
| 구조 다이어그램 | 시스템의 정적인 구조 표현 | 클래스, 객체, 컴포넌트, 배치   |
| 행위 다이어그램 | 시스템의 동적인 행위 표현 | 유스케이스, 시퀀스, 활동, 상태 |

핵심은 `구조 = 정적`, `행위 = 동적`이다.

## 2. 유스케이스 다이어그램

유스케이스 다이어그램은 사용자 관점에서 시스템 기능을 표현한다.

| 요소            | 의미                                  |
| --------------- | ------------------------------------- |
| Actor           | 시스템 외부의 사용자 또는 외부 시스템 |
| Use Case        | 시스템이 제공하는 기능                |
| System Boundary | 시스템 범위                           |
| Association     | Actor와 Use Case의 관계               |
| Include         | 반드시 포함되는 기능                  |
| Extend          | 조건부로 확장되는 기능                |
| Generalization  | 일반화 관계                           |

문제 키워드:

```text
사용자 관점
외부 행위자
시스템 기능
요구사항 분석
include / extend
```

답: `유스케이스 다이어그램`

### Include와 Extend 구분

| 관계    | 의미                    | 예시                 |
| ------- | ----------------------- | -------------------- |
| include | 공통 기능을 반드시 포함 | 로그인 기능 포함     |
| extend  | 조건에 따라 확장        | 쿠폰 적용, 추가 인증 |

암기:

```text
include = 반드시 포함
extend = 선택/조건 확장
```

## 3. 클래스 다이어그램

클래스 다이어그램은 객체지향 시스템의 정적인 구조를 표현한다.

| 요소           | 의미      |
| -------------- | --------- |
| Class          | 클래스    |
| Attribute      | 속성      |
| Operation      | 메서드    |
| Association    | 연관 관계 |
| Aggregation    | 집합 관계 |
| Composition    | 합성 관계 |
| Generalization | 상속 관계 |
| Dependency     | 의존 관계 |

문제 키워드:

```text
클래스
속성
메서드
객체지향 구조
상속
연관
집합/합성
```

답: `클래스 다이어그램`

## 4. 클래스 관계 비교

클래스 다이어그램에서 가장 헷갈리는 부분은 관계다.

| 관계           | 의미                                | 강도      |
| -------------- | ----------------------------------- | --------- |
| Association    | 서로 관련 있음                      | 약함      |
| Aggregation    | 전체-부분, 부분이 독립 가능         | 중간      |
| Composition    | 전체-부분, 전체 소멸 시 부분도 소멸 | 강함      |
| Generalization | 상속, is-a 관계                     | 상속      |
| Dependency     | 일시적으로 사용                     | 약한 의존 |

예시:

```text
자동차 - 바퀴: 집합 또는 합성으로 출제 가능
주문 - 주문상세: 합성 관계로 보기 쉬움
학생 - 과목: 연관 관계
고양이 - 동물: 일반화 관계
```

시험에서는 “전체와 부분의 생명주기”가 나오면 Composition을 의심한다.

## 5. 시퀀스 다이어그램

시퀀스 다이어그램은 객체 간 메시지 전달 순서를 시간 흐름에 따라 표현한다.

| 요소           | 의미                 |
| -------------- | -------------------- |
| Lifeline       | 객체의 생명선        |
| Activation     | 객체가 활성화된 구간 |
| Message        | 객체 간 호출/응답    |
| Return Message | 반환 메시지          |

문제 키워드:

```text
시간 순서
메시지 흐름
객체 간 상호작용
생명선
```

답: `시퀀스 다이어그램`

시퀀스 다이어그램은 “시간”과 “메시지”가 핵심이다.

## 6. 활동 다이어그램

활동 다이어그램은 업무 처리 흐름이나 알고리즘의 흐름을 표현한다.  
흐름도와 비슷하게 생각하면 된다.

| 요소          | 의미      |
| ------------- | --------- |
| Initial Node  | 시작점    |
| Activity      | 활동      |
| Decision Node | 조건 분기 |
| Merge Node    | 병합      |
| Fork/Join     | 병렬 처리 |
| Final Node    | 종료점    |

문제 키워드:

```text
작업 흐름
업무 프로세스
조건 분기
병렬 처리
```

답: `활동 다이어그램`

## 7. 상태 다이어그램

상태 다이어그램은 객체의 상태 변화와 전이를 표현한다.

| 요소          | 의미                   |
| ------------- | ---------------------- |
| State         | 상태                   |
| Transition    | 상태 전이              |
| Event         | 전이를 발생시키는 사건 |
| Initial State | 시작 상태              |
| Final State   | 종료 상태              |

문제 키워드:

```text
상태 변화
이벤트
전이
객체 생명주기
```

답: `상태 다이어그램`

예시:

```text
주문대기 → 결제완료 → 배송중 → 배송완료
```

이런 식으로 상태가 바뀌는 문제가 나오면 상태 다이어그램을 떠올린다.

## 8. ERD

ERD는 Entity Relationship Diagram의 약자다.  
데이터베이스에서 개체와 관계를 표현하는 다이어그램이다.

| 요소         | 의미                  |
| ------------ | --------------------- |
| Entity       | 개체, 테이블 후보     |
| Attribute    | 속성, 컬럼 후보       |
| Relationship | 개체 간 관계          |
| Cardinality  | 1:1, 1:N, N:M 관계 수 |
| Primary Key  | 기본키                |
| Foreign Key  | 외래키                |

문제 키워드:

```text
개체
속성
관계
카디널리티
데이터 모델링
테이블 설계
```

답: `ERD`

## 9. DFD

DFD는 Data Flow Diagram의 약자다.  
시스템에서 데이터가 어떻게 흐르는지 표현한다.

| 요소            | 의미          |
| --------------- | ------------- |
| Process         | 처리, 변환    |
| Data Flow       | 데이터 흐름   |
| Data Store      | 데이터 저장소 |
| External Entity | 외부 개체     |

문제 키워드:

```text
데이터 흐름
처리 프로세스
자료 저장소
외부 개체
구조적 분석
```

답: `DFD`

DFD는 데이터가 어디서 들어오고, 어떤 처리를 거쳐, 어디로 나가는지를 본다.

## 10. 다이어그램 빠른 구분표

| 키워드                          | 다이어그램            |
| ------------------------------- | --------------------- |
| 사용자, Actor, 기능, 요구사항   | 유스케이스 다이어그램 |
| 클래스, 속성, 메서드, 상속      | 클래스 다이어그램     |
| 시간 순서, 메시지, 생명선       | 시퀀스 다이어그램     |
| 업무 흐름, 조건 분기, 병렬 처리 | 활동 다이어그램       |
| 상태, 이벤트, 전이              | 상태 다이어그램       |
| 개체, 속성, 관계, 테이블        | ERD                   |
| 데이터 흐름, 처리, 저장소       | DFD                   |
| 컴포넌트와 인터페이스           | 컴포넌트 다이어그램   |
| 노드, 서버, 배포 환경           | 배치 다이어그램       |

## 11. 시험용 암기 문장

```text
유스케이스 다이어그램은 사용자 관점에서 시스템의 기능과 외부 행위자의 관계를 표현한다.
클래스 다이어그램은 클래스, 속성, 메서드, 클래스 간 관계를 표현한다.
시퀀스 다이어그램은 객체 간 메시지 전달을 시간 순서에 따라 표현한다.
활동 다이어그램은 업무 처리 흐름과 조건 분기, 병렬 처리를 표현한다.
상태 다이어그램은 객체의 상태 변화와 이벤트에 따른 전이를 표현한다.
ERD는 데이터베이스의 개체, 속성, 관계를 표현한다.
DFD는 시스템 내 데이터의 흐름과 처리 과정을 표현한다.
```

## 마무리

다이어그램 문제는 이름만 외우면 헷갈린다.  
반드시 **무엇을 표현하는 다이어그램인지**를 기준으로 외워야 한다.

```text
기능이면 유스케이스
구조면 클래스
시간 순서면 시퀀스
작업 흐름이면 활동
상태 변화면 상태
데이터 구조면 ERD
데이터 흐름이면 DFD
```

시험 직전에는 이 7개만 확실히 구분해도 다이어그램 문제에서 흔들릴 확률이 줄어든다.
