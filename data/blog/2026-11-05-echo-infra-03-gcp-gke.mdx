[Echo 인프라 시리즈 전체 목차](/blog/2026-11-05-echo-infra-series)

> 2026년 11월 4일 기준 해커톤 구현 회고입니다. 당시 코드와 작업 기록을 기준으로 정리했으며, 현재 서비스 상태나 모든 환경에 적용되는 설정을 보장하지 않습니다.

## 기술 명칭과 설명

GKE는 Google Cloud 관리형 Kubernetes입니다. Cloud NAT는 비공개 노드의 외부 통신을 지원합니다. GCP는 서비스별 API를 활성화해야 자원을 생성할 수 있어, 자원 간 관계뿐 아니라 API 활성화 순서도 중요합니다.

## 내가 무엇을 했는가

GCP 서울 dev 루트에 VPC·Cloud NAT·GKE·Artifact Registry·CI 연합·예산 설정을 추가했습니다. AWS와 구분되는 주소 대역과 출력값 계약을 정리하고, GCP에서도 같은 검사·plan 흐름을 사용하도록 만들었습니다.

## 트러블슈팅: 문제 → 원인/판단 → 조치

첫 apply에서 API 활성화와 IAM·고정 IP 생성이 경합할 수 있었습니다. ad1faa7에서 서비스 계정과 IAM은 iam·cloudresourcemanager API 뒤에, 주소 자원은 compute API 뒤에 생성되도록 의존성을 추가했습니다. 단순 재시도가 아니라 첫 구축의 선행 조건을 코드에 반영한 수정입니다.

## 해결 결과와 아직 남은 한계

GKE 기반은 작업 기록상 적용되어 있습니다. 본 문서는 읽기 전용 코드·기록 점검이며 현재 클라우드 상태를 새로 조회한 결과는 아닙니다.

## 발표·면접에서 설명할 문장

> GCP 첫 구축에서 API 활성화 순서를 명시해, 이미 세팅된 프로젝트에서만 우연히 통과하는 코드를 피했습니다.

## 기여 범위와 검증 기준

본인 작성의 비병합 커밋과 변경 내용을 대조했습니다. 코드 구현, 적용 기록, 실측 결과는 구분합니다. 팀원이 만든 기반을 확장한 작업은 그 경계를 본문에 명시했고, 목표 수치는 완료 성과로 표현하지 않았습니다. 운영 경로와 식별자는 공개본에서 생략했습니다.
