2020년 개편 이후 2026년 1회까지 공개된 실기 복원 자료를 훑고, 코드와 SQL 작성 문제를 제외한 **용어형 문제만** 추렸다. 복원 문제는 공식 원문이 아니므로 정확한 출제 횟수를 단정하지 않고 다음 기준으로 우선순위를 나눴다.

```text
S: 여러 연도에 걸쳐 용어군이 반복 출제됨 — 반드시 암기
A: 재출제되었거나 다른 형태로 변형 출제됨 — 합격권 핵심
R: 2025~2026 최근 출제 — 다음 시험 대비
```

## 33점 시험 복기 — 개인 최우선 득점 영역

지난 응시 시험에서 직접 기억나는 출제 영역은 다음 네 가지다.

```text
스텁·드라이버
응집도
결합도
테스트
```

복원 자료의 빈출 영역과 실제 응시 기억이 겹치므로 가장 먼저 점수로 전환해야 한다. 아래 4문장은 문제를 보자마자 답할 수 있을 때까지 반복한다.

```text
하향식 통합 테스트에서 하위 모듈을 대신한다 = 스텁(Stub)
상향식 통합 테스트에서 상위 모듈을 대신한다 = 드라이버(Driver)
모듈 간 의존성은 낮을수록 좋다 = 결합도(Coupling)
모듈 내부 요소의 관련성은 높을수록 좋다 = 응집도(Cohesion)
```

### 무조건 맞히는 5점 후보

실기 한 문항을 5점으로 보고, 아래 유형이 나오면 반드시 득점하는 것을 1차 목표로 한다. 실제 회차의 문제 형식과 배점은 달라질 수 있으므로 **득점 목표 명칭**으로 사용한다.

| 우선순위 | 5점 후보        | 맞히는 기준                             |
| -------- | --------------- | --------------------------------------- |
| 1        | 스텁·드라이버   | 하향식/상향식 설명만 보고 즉시 구분     |
| 2        | 결합도          | 내용·공통·외부·제어·스탬프·자료 구분    |
| 3        | 응집도          | 기능·순차·교환·절차·시간·논리·우연 구분 |
| 4        | 테스트 커버리지 | 문장·결정·조건·조건/결정 구분           |
| 5        | DB 기본 용어    | 튜플·속성·카디널리티·차수·도메인 구분   |

```text
최소 목표: 위 5개 후보 중 출제되는 문제는 전부 정답
학습 방법: 설명을 보고 용어 쓰기 → 용어를 보고 한 줄 정의하기
```

### 모듈과 소프트웨어 설계

| 용어             | 답안 식별 키워드                       |
| ---------------- | -------------------------------------- |
| 결합도(Coupling) | 모듈 간 의존 정도, 낮을수록 좋음       |
| 자료 결합도      | 필요한 단순 데이터만 전달              |
| 스탬프 결합도    | 배열·객체·자료구조 전체 전달           |
| 제어 결합도      | 제어 플래그로 상대 모듈 흐름 결정      |
| 외부 결합도      | 외부 장치·프로토콜·파일 형식 공유      |
| 공통 결합도      | 전역 데이터 영역 공유                  |
| 내용 결합도      | 다른 모듈 내부를 직접 참조·변경        |
| 응집도(Cohesion) | 모듈 내부 요소의 관련성, 높을수록 좋음 |
| 기능적 응집도    | 모든 요소가 하나의 기능 수행           |
| 순차적 응집도    | 앞 활동의 출력이 다음 활동의 입력      |
| 교환적 응집도    | 동일한 입력과 출력을 여러 기능이 사용  |
| 절차적 응집도    | 정해진 절차·순서로 기능 수행           |
| 시간적 응집도    | 같은 시점에 실행되는 기능의 모음       |
| 논리적 응집도    | 유사 기능 중 매개변수로 하나 선택      |
| 우연적 응집도    | 관련 없는 기능의 모음                  |
| Fan-In           | 해당 모듈을 호출하는 상위 모듈 수      |
| Fan-Out          | 해당 모듈이 호출하는 하위 모듈 수      |

```text
결합도 강함 → 약함: 내용-공통-외부-제어-스탬프-자료
응집도 강함 → 약함: 기능-순차-교환-절차-시간-논리-우연
```

## A급 — 변형 출제 대비

### 디자인 패턴

| 용어            | 답안 식별 키워드                         |
| --------------- | ---------------------------------------- |
| Adapter         | 호환되지 않는 인터페이스를 변환·연결     |
| Bridge          | 기능 계층과 구현 계층 분리               |
| Proxy           | 대리 객체가 실제 객체 접근 제어          |
| Decorator       | 객체를 감싸 기능을 동적으로 추가         |
| Facade          | 복잡한 하위 시스템에 단순 통합 창구 제공 |
| Composite       | 단일 객체와 복합 객체를 트리로 동일 취급 |
| Observer        | 한 객체의 상태 변화를 의존 객체에 통지   |
| Strategy        | 알고리즘을 캡슐화하여 교체               |
| Iterator        | 내부 구조를 노출하지 않고 순회           |
| Template Method | 알고리즘 골격은 상위, 세부 구현은 하위   |
| Factory Method  | 객체 생성을 하위 클래스에 위임           |
| Singleton       | 클래스의 인스턴스를 하나만 생성          |

```text

구조: Adapter, Bridge, Composite, Decorator, Facade, Flyweight, Proxy

```

| FEC                    | 재전송 없이 수신 측에서 오류 정정   |
| BEC                    | 오류 발생 시 송신 측에 재전송 요구  |

</details>
