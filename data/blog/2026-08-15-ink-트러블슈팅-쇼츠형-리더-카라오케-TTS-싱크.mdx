## 문제 상황

inKB 리더를 "글로 읽는" 화면에서 "쇼츠처럼 보고 듣는" 화면(세로 스와이프 + 오디오 + **카라오케 하이라이트**)으로 바꾸는 작업. 핵심 난제는 **말하는 소리에 맞춰 글자를 반짝이게** 하는 것 — 즉 TTS 재생 위치와 화면의 단어를 실시간으로 동기화해야 했다.

네이티브 TTS를 붙이는 건 쉽다(`expo-speech`). 문제는 "지금 몇 번째 단어를 읽고 있는가"를 아는 것.

## 원인 분석

`expo-speech`의 `Speech.speak(text, options)`에는 `onBoundary` 콜백이 있고, 단어 경계마다 `charIndex`(원문 내 문자 위치)를 준다. 이걸로 단어 인덱스를 계산하면 정확한 카라오케가 된다.

그런데 **`onBoundary`는 플랫폼마다 동작이 다르다:**

- **iOS**: `AVSpeechSynthesizer`가 단어 경계 이벤트를 잘 준다 → 정밀 싱크 가능.
- **Android**: TTS 엔진에 따라 이벤트가 아예 안 오거나 불규칙하다 → 싱크 불가.

즉 `onBoundary`에만 의존하면 안드로이드에서 카라오케가 죽는다. 또 하나, `onBoundary`의 타입 정의가 `expo-speech` 버전마다 달라서 `SpeechOptions`에 그대로 넣으면 `tsc`가 버전에 따라 깨질 수 있었다.

## 해결 방법

**① 정밀(onBoundary) + 폴백(시간추정) 이중화.** 원문을 공백 기준 토큰으로 쪼개 각 단어의 char offset을 기록해두고:

```ts
function tokenize(text: string) {
  const toks = []
  const re = /\S+/g
  let m
  while ((m = re.exec(text))) toks.push({ text: m[0], start: m.index, end: m.index + m[0].length })
  return toks
}
```

- `onBoundary`가 오면 `charIndex → 단어 인덱스`로 정밀 매핑하고 `boundaryFired = true`.
- 재생 시작(`onStart`)과 동시에 **시간추정 타이머**를 돌린다. `estDur = max(글자수 × 95ms, 1200)`로 총 길이를 추정해 경과 비율로 단어 인덱스를 전진. 단 `boundaryFired`가 true면 타이머는 건드리지 않는다(정밀값이 우선).

결과: **iOS는 정밀 싱크, Android는 부드러운 추정 싱크**로 어디서든 카라오케가 돈다.

**② 버전 독립 타이핑.** `onBoundary` 타입이 버전마다 달라 옵션 객체를 `Record<string, unknown>`으로 만들고 호출부에서 캐스팅:

```ts
;(Speech.speak as (t: string, o: unknown) => void)(text, opts)
```

`@ts-expect-error`는 "지시자가 안 쓰였다"고 되레 에러날 수 있어 지양하고, 호출 캐스팅으로 라이브러리 타입과 분리했다.

**③ 페이지 전환 = 재생 정리.** 세로 페이저(`FlatList pagingEnabled`)에서 페이지가 바뀔 때마다 이전 발화를 `Speech.stop()`하고 새 문장을 재생. 언마운트/전환에서 타이머와 발화를 반드시 정리해 소리가 겹치지 않게 했다.

`expo-speech`는 Expo Go에서 바로 돌아 별도 네이티브 빌드가 필요 없었고, `tsc --noEmit`와 `expo export`(iOS 번들 3.2MB)로 검증했다.

## 배운 점

- **"TTS 붙이기"와 "TTS 싱크"는 난이도가 다르다.** 소리는 쉽지만 위치 추적은 플랫폼 편차가 크다 → 처음부터 정밀+폴백 이중화를 설계에 넣는 게 맞다.
- 크로스플랫폼 이벤트(`onBoundary`류)는 **"있으면 쓰고 없으면 추정"** 패턴이 안전하다.
- 정밀 싱크가 정말 중요하면 결국 **서버 TTS(Google SSML `<mark>` 타임포인트) + 오디오 캐싱**으로 가야 한다(온디바이스 TTS는 음질·타임스탬프 한계). 지금은 프로토타입이라 온디바이스로 충분.
